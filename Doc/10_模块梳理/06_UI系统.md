# UI 系统

## 模块职责

- 负责手牌、棋盘、合同区、HUD、阶段按钮等主要界面
- 负责拖拽出牌、Hover 预览、结算反馈等运行时表现
- 通过事件总线监听游戏状态变化并刷新界面

## 当前实现

### HUD 与主刷新链路

- `UIManager` 继续监听：
  - `PhaseChanged`
  - `MoneyChanged`
  - `CardPlayed`
  - `TurnStarted`
  - `GameOver`
- `UITopBar` 继续负责：
  - 资金文本刷新
  - 累计支出刷新
  - 资金变动时的 `PunchScale`

### 通用跳字反馈链路

当前 V1 已落地的 UI 反馈链路是：

1. 业务层发布结算事件或直接调用适配器
2. `BaoZuPoFeedbackAdapter` 把业务对象映射成通用反馈请求
3. `FeedbackServiceLocator` 把请求路由给运行时反馈服务
4. `FeedbackPlaybackCoordinator` 按目标分轨播放
5. 每条轨道内部复用 `UISequenceTextController`

### 并发策略

- 同一个房间：串行
- 同一个合同卡：串行
- 不同房间/不同合同：并行
- 全局目标：独立一条轨道

### 旧结算控制器的现状

- `UISettlementSequenceController` 仍保留，作为兼容桥存在
- 它不再直接拼装和播放 UI
- 它当前负责：
  - 监听旧的 `SettlementSequenceQueued`
  - 转交给通用反馈模块
  - 在结算反馈全部播放结束后刷新棋盘 UI

## 降级与保底

- `UIManager` 在启动时尝试初始化 `FeedbackBootstrap`
- 模块关闭、未初始化或播放器不可用时，会自动退化到 `NoOpFeedbackService`
- 退化后游戏只是不显示跳字，不会阻断：
  - 结算
  - 出牌
  - 贷款
  - `GameOver`

## 当前限制

- V1 使用代码创建的运行时反馈轨道，没有要求额外 prefab 配置
- 反馈模块当前只覆盖资金相关表现
- 旧的 `UISettlementSequenceData` 仍保留在工程中，作为过渡兼容资产，不再是主链路

## 修改准则

- HUD 数值刷新不要并入反馈模块
- 业务规则不要下沉到 UI 或动画工具类
- 新增反馈优先走通用反馈服务，不要重新回到“业务脚本直接操作播放器”

## 手工验收点

- 多个房间同回合结算时是否能并行播放
- 同一个房间的基础/加成/最终值是否按顺序播放
- 合同结算与房间结算是否互不阻塞
- 关闭反馈模块后，UI 是否仍能正常刷新且不报错
- 回合结束后，耐久/等待变化是否能在 UI 上及时体现
