- 负责手牌、棋盘、合同区、HUD、阶段面板、结算表现和奖励面板等主要界面显示。
- 负责拖拽出牌、Tooltip 预览、结算跳字反馈和奖励三选一交互。
- 负责根据 `GameEvents` 刷新玩家可见内容。
- 当前固定文案真源已经收口到 [GameText.cs](../../Assets/Scripts/Runtime/UI/GameText.cs)。

## 当前实现

### UIManager 主链路

`UIManager` 当前监听：

- `PhaseChanged`
- `CardPlayed`
- `TurnStarted`
- `GameOver`
- `CardRewardOffered`

它负责：

- 刷新 HUD、手牌和棋盘
- 初始化拖拽控制器
- 安装 Tooltip 接线
- 同步资金反馈开关配置
- 收到奖励事件后显示 `UICardRewardPanel`

### 手牌与棋盘

- `UIHandPanel` 根据 `DeckManager.Hand` 实例化手牌 UI。
- `UIHandPanel` 内部使用 `UnityEngine.Pool.ObjectPool<GameObject>` 复用抽牌 Ghost 和弃牌 Ghost；正式手牌视图仍按手牌状态同步创建/销毁。
- `UIBoardPanel` 根据 `BoardManager` 刷新房间、合同和场上牌。
- `UIRoomView / UIRoomSlotView` 根据 `RoomSlot` 容量动态生成格位。
- `UICardView` 负责玩家可见卡牌信息与交互状态。
- 手牌上下文中，`UICardView` 显示名称、费用、描述、类型标签、等待、租金和耐久等完整信息；租金只在租客卡且 `baseRent > 0` 时显示，耐久只在当前耐久 `> 1` 时显示。

### 拖拽出牌

1. `UICardDragHandler` 负责手牌卡面的拖拽输入。
2. `UICardDragController` 接管真正的拖拽对象。
3. `UICardDropZone` 根据卡牌目标类型决定高亮与接收。
4. 松手时先调用注入的 `CardPlayService.ValidatePlay(...)`。
5. 合法则播放飞牌并执行 `CardPlayService.Play(...)`；`TurnManager.ValidatePlay / PlayCard` 只保留兼容入口。
6. 非法则抖动并回弹。

### 结算表现与反馈

- `UISettlementSequenceController` 接收 `UISettlementPlaybackBatch`。
- 结算 step 和最终入账固定走 `UIFeedbackPopupLayer` / `UIFeedbackPopupView`。
- `UIFeedbackPopupLayer` 内部使用 `UnityEngine.Pool.ObjectPool<UIFeedbackPopupView>` 复用 popup；单个 popup 播放完成后 release 回池，并清理 tween、文本、透明度、缩放和交互状态。
- 结算数字累计视图使用场景中的 `transferLabel / roomAccumulatorLabel / accumulatorLabel` 单实例复用，不在播放过程中逐次创建或销毁数字对象。
- `BaoZuPoFeedbackAdapter` 负责把出牌扣款、即时资金变化、贷款扣款映射成 popup 请求。
- popup 位置由 `Anchor + ScreenOffset` 决定；钱栏相关 popup 通过 `UITopBar.MoneyTargetAnchor` 定位。
- `UITopBar.PlayCostPopupVerticalGap` 调整出牌/贷款扣款高度，`UITopBar.SettlementTotalPopupVerticalGap` 调整最终入账高度。
- `UITopBar` 默认尊重场景中已绑定文本的父物体和布局，只有运行时补齐文本时才应用默认布局。

### Tooltip

Tooltip 当前是“通用模块本体 + 可选运行时模块 + 项目接线层”的结构：

- 模块本体位于 `Assets/Modules/Martian/Tooltip/`
- 运行时模块位于 `Assets/Modules/Martian/Tooltip/Runtime/`
- 项目 presenter 位于 [BaoZuPoCardTooltipPresenter.cs](../../Assets/Scripts/Runtime/Integration/Martian/Tooltip/BaoZuPoCardTooltipPresenter.cs)
- 项目安装入口位于 [BaoZuPoMartianTooltipIntegration.cs](../../Assets/Scripts/Runtime/Integration/Martian/Tooltip/BaoZuPoMartianTooltipIntegration.cs)

运行时模块缺失时，会通过 `NullTooltipService` 安静降级，只影响显示，不影响流程。

### 奖励三选一

- `RewardService` 发布 `CardRewardOffered`
- `UIManager.OnCardRewardOffered(...)` 调用 `UICardRewardPanel.Show(...)`
- `UICardRewardPanel` 生成最多 3 张不重复候选卡
- 玩家点击卡牌或“Skip”后，面板发布 `CardRewardSelected`
- `RewardService` 等待选择结果，`TurnManager` 负责奖励入手动画并结束本回合

这条链路不是可选模块，而是主流程的一部分。

### 当前文案真源

当前主干实际运行的是：

- `GameText` 作为 UI 固定文案调用面
- Unity Localization `GameText` 表作为运行时解析来源
- 当前默认 zh-Hans
- 无运行时语言切换 UI
- TMP 字体由 `Martian.Localization` 自动应用 SourceHanSansSC

`Martian.Localization` 和 `com.unity.localization` 已接线启用；UI 层不要绕过 `GameText` 直接硬编码玩家可见文案。

## 与其他模块的依赖

- 回合系统：通过 `GameEvents` 接收阶段变化、回合变化、结算播放完成和奖励事件。
- 棋盘系统：棋盘与房间 UI 直接读取 `BoardManager`、`RoomSlot`。
- 牌库系统：手牌区直接读取 `DeckManager`。
- 经济系统：顶栏金额与统计依赖 `MoneyManager`。

## 当前限制与风险

- `UICardRewardPanel` 属于主链路必需引用；场景或 prefab 没配好时会直接报错暴露问题。
- 奖励池唯一候选不足 3 张时，会 warning 并退化为更少选项。
- Tooltip 可降级，但结算/资金 popup 已是 UI 主链路的一部分；奖励面板不能按同样方式静默降级。
- 本地化表、字体 profile 和 UI prefab 配置需要一起验收；新增文案后只改 `GameText.cs` 不同步表，会导致运行时继续显示 fallback。
- Phase 6 当前已完成 popup、抽牌 Ghost、弃牌 Ghost 和 transient feedback track 池化；结算数字确认是单实例复用，剩余风险主要在 Unity Editor 实机多回合残留验证。

## 修改准则

- UI 不承接玩法规则判断，规则仍由 `CardPlayService`、`RewardService`、`ShopService`、`TurnManager` 兼容门面、`CardTargeting` 和底层系统负责。
- `UICardDragController.SetCardPlayService(...)` 已接入 VContainer 注入；场景未启用 `GameLifetimeScope` 时仍会 fallback 到默认 service，方便过渡期验收。
- 新增玩家可见固定文案时，优先接入 [GameText.cs](../../Assets/Scripts/Runtime/UI/GameText.cs)。
- 不要重新引入 `UseChinese` 或散落的运行时字体切换状态；如需语言切换，应扩展现有本地化服务链路。
- Tooltip 的可选化边界不要反向污染主流程 UI；资金 popup 通用层不要直接依赖 Feel 或业务语义。
- 新增 UI 模块时，要同步补 [UI手动配置与验收.md](./UI手动配置与验收.md)。

## 手工验收点

- 开局后手牌、房间、合同区、顶栏和阶段面板是否都能正常显示。
- 租客、设备、事件牌拖到合法区域是否成功。
- 非法拖放是否能正确回弹。
- 结算跳字是否按顺序播放。
- 出牌扣款、贷款扣款和结算最终入账是否出现在 `Money Target Anchor` 上方。
- 结算后奖励面板是否能弹出。
- 奖励选择与跳过是否都能推进到下一回合。
- 移除 Tooltip 运行时模块后，是否只失去 Tooltip 显示，而不是阻断主流程。
