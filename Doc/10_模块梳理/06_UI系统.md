# UI系统

## 模块职责

- 负责手牌、棋盘、合同区、HUD、阶段按钮等主要界面展示。
- 负责拖拽出牌、Hover 预览、结算跳字等交互表现。
- 通过事件总线监听游戏状态变化并刷新界面。

## 当前实现

### 刷新主链路

[UIManager.cs](../../Assets/_Assets/Scripts/UI/UIManager.cs) 会在以下事件上刷新主要 UI：

- `PhaseChanged`
- `MoneyChanged`
- `CardPlayed`
- `TurnStarted`
- `GameOver`

### 手牌与棋盘

- [UIHandPanel.cs](../../Assets/_Assets/Scripts/UI/UIHandPanel.cs) 根据 `DeckManager.Hand` 实例化手牌。
- [UIBoardPanel.cs](../../Assets/_Assets/Scripts/UI/UIBoardPanel.cs) 根据 `BoardManager` 刷新房间和合同区。
- [UIRoomView.cs](../../Assets/_Assets/Scripts/UI/UIRoomView.cs) 现在按 `RoomSlot.TenantSlotCapacity` 和 `RoomSlot.EquipmentSlotCapacity` 动态生成槽位，不再写死 `1 租客 + 3 设备`。

### 拖拽出牌

当前主路径是拖拽而不是点击选目标：

1. `UICardDragHandler` 仅绑定手牌卡面。
2. `UICardDragController` 接管真实出牌对象。
3. `UICardDropZone` 根据当前卡牌类型决定高亮与接收。
4. 松手时先调用 `TurnManager.ValidatePlay(...)`。
5. 合法则播放飞牌并执行 `TurnManager.PlayCard(...)`。
6. 非法则抖动并回弹。

### Hover 与结算表现

- `HoverPreviewController` 统一维护一个预览 Overlay。
- `UISettlementSequenceController` 监听 `SettlementSequenceQueued`。
- `UISequenceTextController` 负责 DOTween 跳字表现。

## 与其他模块的依赖

- 回合系统：
  - 通过 `GameEvents` 接收阶段变化、回合变化、GameOver。
- 棋盘系统：
  - 棋盘与房间 UI 直接读取 `BoardManager` / `RoomSlot`。
- 牌库系统：
  - 手牌区直接读取 `DeckManager`。
- 经济系统：
  - 顶栏资金与统计依赖 `MoneyManager` 事件。

## 当前限制与风险

- 虽然房间槽位已经跟随真实容量生成，但更多棋盘样式差异目前仍主要靠代码拼装，不是完整 prefab 规范化方案。
- 仍有一部分交互骨架依赖运行时补节点，例如拖拽层、Hover Overlay、结算跳字 Overlay、部分高亮节点。
- 玩家可见固定文案仍有不少英文，和“中文优先”的近期目标不完全一致。
- `UIPhasePanel` 当前仍存在场景引用缺失时依赖运行时兜底的情况。

## 修改准则

- UI 不承接玩法规则判断，规则由 `TurnManager`、`CardTargeting` 和底层系统负责。
- 允许保留少量运行时补节点，但高频、易错、影响美术配置的关键引用应逐步显式化。
- 修改拖拽、Hover、结算表现链路时，必须回归主出牌流程。
- 新增房型或扩容机制时，优先沿用 `RoomSlot` 容量驱动 UI，不要重新引入写死槽位。

## 手工验收点

- 开局后手牌、房间、合同区是否都能正常显示。
- 设备扩容后，房间 UI 是否在刷新后显示新增槽位。
- 拖拽租客、设备、事件到合法区域是否成功。
- 非法释放时是否回弹。
- 场上卡 Hover 是否正常。
- 结算跳字是否能在房间、合同、事件来源上按预期播放。
