# UI系统

## 模块职责

- 负责手牌、棋盘、合同区、HUD、阶段面板、结算表现和奖励面板等主要界面展示。
- 负责拖拽出牌、Tooltip 预览、结算跳字反馈和奖励三选一交互。
- 负责根据 `GameEvents` 和当前语言状态刷新玩家可见内容。

## 当前实现

### UIManager 主链路

`UIManager` 当前监听：

- `PhaseChanged`
- `CardPlayed`
- `TurnStarted`
- `GameOver`
- `CardRewardOffered`
- `LocalizationManager.LanguageChanged`

它负责：

- 刷新 HUD、手牌、棋盘
- 初始化拖拽控制器
- 安装 Tooltip 项目接线
- 初始化反馈模块入口
- 收到奖励事件后显示 `UICardRewardPanel`
- 切语言时刷新字体和奖励面板文案

### 手牌与棋盘

- `UIHandPanel` 根据 `DeckManager.Hand` 实例化手牌 UI
- `UIBoardPanel` 根据 `BoardManager` 刷新房间、合同和场上牌
- `UIRoomView` / `UIRoomSlotView` 根据 `RoomSlot` 容量动态生成格子
- `UICardView` 负责玩家可见卡牌信息与交互状态

### 拖拽出牌

当前主路径仍然是“拖拽而不是点选目标”：

1. `UICardDragHandler` 负责手牌卡面的拖拽输入
2. `UICardDragController` 接管真正的拖拽对象
3. `UICardDropZone` 根据卡牌目标类型决定高亮与接收
4. 松手时先调用 `TurnManager.ValidatePlay(...)`
5. 合法则播放飞牌并执行 `TurnManager.PlayCard(...)`
6. 非法则抖动并回弹

### 结算表现与反馈

- `UISettlementSequenceController` 接收 `UISettlementPlaybackBatch`
- `FeedbackBootstrap` 和 `FeedbackPlaybackCoordinator` 负责调度跳字反馈
- `BaoZuPoFeedbackAdapter` 负责把项目侧结算、出牌、贷款语义映射成通用反馈请求
- 当前反馈模块缺失时仍允许降级为 no-op，不阻断主链路

### Tooltip

Tooltip 当前是“通用模块本体 + 可选运行时模块 + 项目接线层”结构：

- 模块本体位于 `Assets/_Assets/Martian/Tooltip/`
- 运行时模块位于 `Assets/_Assets/Martian/Tooltip/Runtime/`
- 当前项目卡牌 presenter 位于 [BaoZuPoCardTooltipPresenter.cs](../../Assets/_Assets/Scripts/Integration/Martian/Tooltip/BaoZuPoCardTooltipPresenter.cs)
- 当前安装入口位于 [BaoZuPoMartianTooltipIntegration.cs](../../Assets/_Assets/Scripts/Integration/Martian/Tooltip/BaoZuPoMartianTooltipIntegration.cs)

运行时模块缺失时，会通过 `NullTooltipService` 安静降级，只影响显示，不影响流程。

### 奖励三选一

- `TurnManager` 发布 `CardRewardOffered`
- `UIManager.OnCardRewardOffered(...)` 调用 `UICardRewardPanel.Show(...)`
- `UICardRewardPanel` 生成 3 张候选卡
- 玩家点击卡牌或“跳过”后，面板发布 `CardRewardSelected`
- `TurnManager` 收到结果后决定是否把奖励卡加入手牌并结束本回合

这条链路当前不是可选模块，而是主流程的一部分。

### 当前运行时本地化真源

当前主干实际在跑的是：

- `LocalizationManager`
- `UIStrings`
- `UIFontCatalog`

仓库中虽然已经导入 `Martian.Localization` 与 `com.unity.localization`，但 UI 主链路还没有接到那套模块化本地化能力上。

## 与其它模块的依赖

- 回合系统
  - 通过 `GameEvents` 接收阶段变化、回合变化、结算播放完成和奖励事件
- 棋盘系统
  - 棋盘与房间 UI 直接读取 `BoardManager`、`RoomSlot`
- 牌库系统
  - 手牌区直接读取 `DeckManager`
- 经济系统
  - 顶栏金额与统计依赖 `MoneyManager`
- 本地化
  - 当前 UI 文案刷新依赖 `LocalizationManager + UIStrings + UIFontCatalog`

## 当前限制与风险

- `UICardRewardPanel` 当前属于主链路必需引用；如果场景或 prefab 没配好，现在会在启动或展示时直接报错暴露问题。
- 奖励面板内部引用和奖励卡 prefab 现在都按主链路契约处理，Inspector/Prefab 完整性要求比之前更高。
- Tooltip 和反馈模块可以降级，但奖励面板不可以按同样方式静默降级。
- 当前仓库中并存“旧 UI 本地化实现”和“已导入未接线的新本地化模块”，维护时必须明确真源。

## 修改准则

- UI 不承接玩法规则判断，规则仍由 `TurnManager`、`CardTargeting` 和底层系统负责。
- 奖励链路属于主流程，缺配置应优先暴露，不应静默吞掉。
- Tooltip 与反馈的可选化边界不要反向污染主流程 UI。
- 新增玩家可见固定文案时，优先接入当前真源 `UIStrings`，并同步验证 `UIFontCatalog`。
- 新增 UI 模块时，要同步补 [UI手动配置与验收.md](./UI手动配置与验收.md)。

## 手工验收点

- 开局后手牌、房间、合同区、顶栏和阶段面板是否都能正常显示
- 租客、设备、事件牌拖到合法区域是否成功
- 非法拖放是否能正确回弹
- 结算跳字是否按顺序播放
- 结算后奖励面板是否能弹出
- 奖励选择与跳过是否都能推进到下一回合
- 切换语言后，顶栏、GameOver、奖励面板和固定文案是否同步刷新
- 移除 Tooltip 运行时模块后，是否只是失去 Tooltip 展示，而不是阻断主游戏流程
