# UI系统

## 模块职责

- 负责手牌、棋盘、合同区、HUD、阶段按钮等主要界面展示。
- 负责拖拽出牌、Tooltip 预览、结算跳字等交互表现。
- 通过事件总线监听游戏状态变化并刷新界面。

## 当前实现

### HUD与主刷新链路

- `UIManager` 继续监听：
  - `PhaseChanged`
  - `MoneyChanged`
  - `CardPlayed`
  - `TurnStarted`
  - `GameOver`
- `UITopBar` 继续负责：
  - 资金文本刷新
  - 累计支出刷新
  - 资金变动时的 `PunchScale`

### 手牌与棋盘

- [UIHandPanel.cs](../../Assets/_Assets/Scripts/UI/UIHandPanel.cs) 根据 `DeckManager.Hand` 实例化手牌。
- [UIBoardPanel.cs](../../Assets/_Assets/Scripts/UI/UIBoardPanel.cs) 根据 `BoardManager` 刷新房间和合同区。
- [UIRoomView.cs](../../Assets/_Assets/Scripts/UI/UIRoomView.cs) 按 `RoomSlot.TenantSlotCapacity` 和 `RoomSlot.EquipmentSlotCapacity` 动态生成槽位。

### 拖拽出牌

当前主路径是拖拽而不是点击选目标：

1. `UICardDragHandler` 仅绑定手牌卡面。
2. `UICardDragController` 接管真实出牌对象。
3. `UICardDropZone` 根据当前卡牌类型决定高亮与接收。
4. 松手时先调用 `TurnManager.ValidatePlay(...)`。
5. 合法则播放飞牌并执行 `TurnManager.PlayCard(...)`。
6. 非法则抖动并回弹。

### Tooltip可选模块

当前 Tooltip 已按“宿主稳定层 + 可抽离运行时模块 + 项目卡牌适配层”拆分：

- 宿主稳定层位于 `UI/Common/Tooltip/`
  - 提供 `ITooltipService`、`ITooltipContentProvider`、`TooltipRequest`、`TooltipContent`、`TooltipTrigger`、`TooltipServices`
  - `TooltipServices.Current` 默认返回 no-op 的 `NullTooltipService`
- 运行时模块位于 `UI/Common/Tooltip/Runtime/`
  - 提供 `TooltipRuntimeService`
  - 首次显示时按 `Anchor` 所属 `Canvas` 懒创建 `TooltipRuntimeRoot`
  - 支持 `FollowPointer` 与 `AnchorRect` 两种定位模式
- 当前卡牌 presenter 位于 [CardTooltipPresenter.cs](../../Assets/_Assets/Scripts/UI/Common/Tooltip/Runtime/CardTooltipPresenter.cs)
  - 负责把 `TooltipContentKind.Card` 映射到现有卡牌放大预览
  - 为了保证运行时模块可整块移除，presenter 放在 Tooltip Runtime 内，并通过反射读取当前项目卡牌视图

### 当前Tooltip行为

- 手牌、房间租客、房间设备、合同区统一通过 `TooltipTrigger + ITooltipContentProvider` 触发。
- 拖拽开始、阶段切换、回合切换、GameOver、`RefreshAll()` 时都会执行 `TooltipServices.Current.HideAll()`。
- 移除 Tooltip 运行时模块后，调用链仍然存在，但会自动退化为 no-op，不影响游戏流程。

### 通用跳字反馈链路

当前 V1 已落地的 UI 反馈链路是：

1. 业务层发布结算事件或直接调用适配器。
2. `BaoZuPoFeedbackAdapter` 把业务对象映射成通用反馈请求。
3. `FeedbackServiceLocator` 把请求路由给运行时反馈服务。
4. `FeedbackPlaybackCoordinator` 按目标分轨播放。
5. 每条轨道内部复用 `UISequenceTextController`。

### 并发策略

- 同一个房间：串行。
- 同一个合同卡：串行。
- 不同房间/不同合同：并行。
- 全局目标：独立一条轨道。

### 旧结算控制器的现状

- `UISettlementSequenceController` 仍保留，作为兼容桥存在。
- 它不再直接拼装和播放 UI。
- 它当前负责：
  - 监听旧的 `SettlementSequenceQueued`
  - 转交给通用反馈模块
  - 在结算反馈全部播放结束后刷新棋盘 UI

## 降级与保底

- `UIManager` 在启动时尝试初始化 `FeedbackBootstrap`。
- 反馈模块关闭、未初始化或播放器不可用时，会自动退化到 `NoOpFeedbackService`。
- Tooltip 运行时模块缺席时，会自动退化到 `NullTooltipService`。
- 退化后游戏只是不显示跳字或 Tooltip，不会阻断：
  - 结算
  - 出牌
  - 贷款
  - `GameOver`

## 与其他模块的依赖

- 回合系统：
  - 通过 `GameEvents` 接收阶段变化、回合变化、GameOver。
- 棋盘系统：
  - 棋盘与房间 UI 直接读取 `BoardManager`、`RoomSlot`。
- 牌库系统：
  - 手牌区直接读取 `DeckManager`。
- 经济系统：
  - 顶栏资金与统计依赖 `MoneyManager` 事件。

## 当前限制与风险

- 虽然 Tooltip 运行时模块已可整块移除，但宿主层仍会永久保留一层 no-op 契约壳，以保证业务代码不因模块缺席而编译失败。
- 当前项目的卡牌 Tooltip 仍依赖复制卡牌 prefab 做放大预览，这部分是项目适配策略，不是通用 Tooltip Core。
- 反馈模块当前仍主要覆盖资金相关表现，后续如果扩到更多结算内容，需要继续复用现有反馈链路而不是旁路实现。
- 仍有一部分交互骨架依赖运行时补节点，例如拖拽层、`PlayAreaDropZone`、结算跳字容器。
- 旧的 `UISettlementSequenceData` 仍保留在工程中，作为过渡兼容资产，不再是主链路。
- 玩家可见固定文案仍有不少英文，和“中文优先”的近期目标不完全一致。

## 修改准则

- UI 不承接玩法规则判断，规则由 `TurnManager`、`CardTargeting` 和底层系统负责。
- HUD 数值刷新不要并入反馈模块。
- Tooltip 缺席时必须静默降级，不允许中断主流程。
- 修改拖拽、Tooltip、结算表现链路时，必须回归主出牌流程。
- 新增 Tooltip 内容类型时，优先扩展 presenter 与 content provider，不要把业务类型再塞回 Tooltip Core。
- 新增反馈优先走通用反馈服务，不要重新回到“业务脚本直接操作播放器”。
- 新增房型或扩容机制时，优先沿用 `RoomSlot` 容量驱动 UI，不要重新引入写死槽位。

## 手工验收点

- 开局后手牌、房间、合同区是否都能正常显示。
- 设备扩容后，房间 UI 是否在刷新后显示新增槽位。
- 手牌、房间租客、房间设备、合同区 Tooltip 是否都能正常显示。
- 拖拽租客、设备、事件到合法区域是否成功。
- 非法释放时是否回弹。
- 拖拽开始、阶段切换、回合切换、GameOver 时 Tooltip 是否自动关闭。
- 多个房间同回合结算时是否能并行播放。
- 同一个房间的基础、加成、最终值是否按顺序播放。
- 合同结算与房间结算是否互不阻塞。
- 移除 Tooltip 运行时模块或关闭反馈模块后，是否仅失去对应表现，不影响主游戏流程。
- 回合结束后，耐久、等待变化是否能在 UI 上及时体现。
