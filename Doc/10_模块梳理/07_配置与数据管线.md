# 配置与数据管线

## 模块职责

- 管理运行时真正读取的配置资产与资源资产。
- 管理卡牌总资产与卡牌库资产的分层关系。
- 明确 `Excel / ScriptableObject / Doc/40_外部资料` 各自扮演的角色。

## 核心数据结构

### `GameConfig`

- 经济：
  - `startingMoney`
  - `loanAmount`
  - `loanInterval`
  - `loanGrowthFactor`
- 抽牌与奖励：
  - `firstTurnDrawCount`
  - `normalTurnDrawCount`
  - `maxHandSize`
  - `firstTurnDrawLibrary`
  - `normalTurnDrawLibrary`
  - `rewardLibrary`
- 房间：
  - `initialRoomCount`
  - `defaultTenantSlots`
  - `defaultEquipmentSlots`

### `CardData`

- `cardId`
- `cardName`
- `description`
- `cardType`
- `rarity`
- `targetKind`
- `preEffect / instantEffect / settleEffect / destroyEffect`
- `durability`
- `waitTurns`
- 说明：
  - `targetKind` 是出牌目标真源。
  - `cardType` 不再决定“必须打到哪里”，只保留类型语义和房间内分类语义。

### `CardLibrary`

- `libraryId`
- `displayName`
- `cards`

## 当前实现

### 运行时真正读取的数据源

当前运行时真正读取的是：

- [GameConfig.asset](../../Assets/Data/Config/GameConfig.asset)
- `Assets/Resources/Cards/*.asset`
- `Assets/Resources/CardLibraries/*.asset`

不是：

- `Doc/40_外部资料/` 下的 Excel / PDF 参考资料
- 评审文档和专题方案中的示例表格

### 卡牌总资产与牌库资产的关系

- `CardDatabase` 负责加载所有 `CardData` 资产，并承担启动期卡牌效果与目标配置校验的输入集合。
- `CardLibraryDatabase` 负责加载所有 `CardLibrary` 资产，并校验 `libraryId`、卡列表与 `GameConfig` 引用。
- `DeckManager` 抽牌/奖励并不直接从 `CardDatabase.GetAll()` 取，而是从 `GameConfig` 指向的具体 `CardLibrary` 取。

### Excel 与资产的关系

- Excel 仍是内容录入入口。
- [CardDataImporter.cs](../../Assets/Scripts/Editor/CardDataImporter.cs) 负责把 Excel 转成 `Resources/Cards` 下的 `CardData` 资产。
- 运行时只读最终生成的 `.asset`，不直接读 Excel。
- `targetKind` 已进入 `CardData`，要求在内容录入阶段显式填写，并作为出牌目标真源使用。

## 与其他模块的依赖

- 核心流程：
  - `GameManager` 启动时同时加载 `CardDatabase` 与 `CardLibraryDatabase`
  - `GameConfig` 决定哪套牌库用于首回合、普通回合与奖励
- 牌库系统：
  - `DeckManager` 按 `GameConfig.*Library` 随机生成运行时卡实例
- 卡牌系统：
  - `CardInstance` 运行时依赖 `CardData`
- 编辑器工具：
  - 导表脚本维护 `Resources/Cards`
  - `CardLibraries` 当前仍主要通过手工资产维护

## 当前限制与风险

- 卡牌总资产与牌库资产已经分层，但 `CardLibraries` 目前仍缺少自动化导表或一致性工具。
- 导表不会自动清理“Excel 已删除但 `Resources/Cards` 仍残留”的旧资产。
- 新增 `GameConfig` 字段或 `CardLibrary` 资产后，需要同时检查场景引用与运行时校验是否同步。
- `Doc/40_外部资料/` 只是参考区，不应被误认为配置真源。

## 修改准则

- 改全局平衡参数时，优先改 `GameConfig.asset`，并核对脚本字段是否已序列化。
- 改卡牌内容时，优先走 `Excel -> 导表 -> 资产` 链路，不要长期手改生成资产。
- 改抽牌/奖励来源时，优先改 `GameConfig.*Library` 和 `CardLibraries/*.asset`，不要把库选择逻辑重新写回 `TurnManager`。
- 外部资料目录只做参考，不参与运行时配置。

## 手工验收点

- `GameConfig.asset` 是否与 `GameConfig.cs` 字段一致。
- `GameManager` 启动时是否能同时通过卡牌资产和牌库资产校验。
- 首回合抽牌、普通回合抽牌、奖励三选一是否命中正确牌库。
- 新增或删除卡牌后，卡牌总资产与奖励池是否与预期一致。
