# 经济系统

## 模块职责

- 管理当前资金与累计支出
- 提供加钱、扣钱、可支付判断
- 配合 `TurnManager` 处理贷款扣款与失败判定
- 向 UI 和反馈模块发布资金变化结果

## 当前实现

### 资金数值

- `MoneyManager.AddMoney(int amount)`
  - 只接收正数
  - 成功后广播 `MoneyChanged`
- `MoneyManager.ReduceMoney(int amount)`
  - 金额不足时广播 `MoneyInsufficient`
  - 成功后更新累计支出并广播 `MoneyChanged`
- `MoneyManager.CanAfford(int amount)`
  - 用于出牌前校验

### 贷款逻辑

- 贷款逻辑仍由 `TurnManager.ExecuteSettlePhase()` 驱动
- 贷款金额按 `baseAmount * growthFactor ^ loanPaymentCount` 计算
- 支付成功时：
  - 真实扣款仍走 `MoneyManager`
  - 负向跳字反馈走通用反馈模块
- 支付失败时：
  - 不播放伪扣款反馈
  - 直接进入 `GameOver`

### 与跳字反馈模块的边界

- 真实数值变化仍以 `MoneyManager` 为唯一真源
- 经济系统不直接创建 UI 播放请求
- 与“为什么加/减了多少钱、锚到哪里、播成什么样”相关的逻辑，统一交给：
  - `TurnManager`
  - `BaoZuPoFeedbackAdapter`
  - 通用反馈模块

当前 V1 已落地的资金反馈场景：

- 房间基础租金
- 房间附加收益
- 房间结算最终值
- 合同结算收益
- 出牌费用扣减
- 事件牌即时收益
- 合同牌即时收益
- 贷款扣款

## 当前限制

- V1 只接了资金全链路，没有把耐久/等待改造成统一数值反馈入口
- 贷款规则仍在 `TurnManager` 内，后续如经济规则明显变复杂，再考虑拆服务
- `MoneyChanged` 仍然是通用 UI 刷新事件，不携带详细业务原因；详细表现语义由反馈适配层补足

## 修改准则

- 不要让 UI 或反馈模块反向决定真实经济结果
- 任何新经济规则都优先先接入真实数值链路，再决定是否补反馈表现
- 如要新增耐久/等待类跳字，不要继续散落写字段，先收口统一入口

## 手工验收点

- 出牌费用不足时是否正确拦截
- 正常出牌时是否同时看到资金扣减和 HUD 刷新
- 房间/合同结算时是否能按顺序看到资金反馈
- 贷款回合是否按间隔触发
- 贷款成功时是否播放全局负向反馈
- 贷款失败时是否直接进入 `GameOver` 且不因反馈模块报错
