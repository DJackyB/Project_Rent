# 牌库与奖励系统

## 模块职责

- 管理首回合抽牌库、普通回合抽牌库和奖励库三类卡牌来源。
- 管理手牌、弃牌和奖励入手行为。
- 负责当前“三选一奖励”链路在回合与 UI 之间的真实实现说明。

## 当前实现

### 牌库真源

当前回合抽牌和奖励发牌的真源是：

- `Assets/Resources/CardLibraries/*.asset`
- `GameConfig.asset` 中对三类 `CardLibrary` 的显式引用

`CardDatabase` 仍然是卡牌资产与效果校验入口，但不再直接承担“当前回合从哪堆里抽牌”的职责。

### 抽牌方式

- 首回合抽牌数来自 `GameConfig.firstTurnDrawCount`
- 普通回合抽牌数来自 `GameConfig.normalTurnDrawCount`
- 具体从哪套库抽，由 `GameConfig.firstTurnDrawLibrary / normalTurnDrawLibrary` 决定
- `DeckManager.DrawFromLibrary(...)` 当前不是从真实 draw pile 里 pop，而是从指定 `CardLibrary.cards` 中随机生成新的 `CardInstance`

这意味着当前更接近：

- “按配置库随机生成手牌/奖励牌”

而不是：

- 带份数、耗尽、洗回、来源追踪的完整 deckbuilding 牌堆

### 手牌与弃牌

- 出牌成功后会从手牌移除
- 奖励卡入手时：
  - 手牌未满 -> 直接加入手牌
  - 手牌已满 -> 直接进入弃牌堆
- `ResolveHandWaitAndDiscardExpired()` 会在结算期处理手牌中的等待倒计时

### 奖励三选一

当前主链路已经是可视化的玩家选择，而不是旧的自动随机占位：

1. `TurnManager` 在结算播放完成后启动奖励流程
2. `RewardService.OfferAndWaitChoiceAsync(...)` 按 `rewardLibrary` 抽出最多 3 个不重复候选项并发布 `GameEvents.CardRewardOffered`
3. `UIManager` 接到事件后显示 `UICardRewardPanel`
4. 玩家点击某张卡或点击跳过，UI 发布 `GameEvents.CardRewardSelected`
5. `RewardService` 等待并返回选择结果，`TurnManager` 继续处理：
   - 选卡 -> 调用 `DeckManager.AddCardToHand(...)`
   - 跳过 -> 不发牌
6. 奖励结算完后才真正发布 `TurnEnded`

### 加成奖励规则

- 普通奖励：从 `rewardLibrary.cards` 全量候选
- 加成奖励：优先只从 `rarity >= Rare` 的卡中候选
- 如果加成奖励池为空：记录 warning，并回退到 `rewardLibrary.cards` 全量候选
- 当前奖励展示不允许重复候选；同一卡在同一次奖励面板里只会出现一次
- 如果当前池中唯一候选不足 3 张：记录 warning，并只展示可用的唯一候选

## 与其他模块的依赖

- 配置与数据：
  - `GameConfig` 负责声明三类牌库引用
  - `CardLibraryDatabase` 在启动期做库级校验
- 回合流程：
  - `TurnManager` 驱动准备期抽牌、结算后奖励入手动画与回合结束
  - `RewardService` 负责奖励候选生成和等待选择
  - `ShopService` 负责商店开关、购买、关闭和单回合状态
- UI：
  - `UICardRewardPanel` 负责奖励选择交互
  - `UIHandPanel` 直接读取 `DeckManager.Hand`

## 当前限制与风险

- 当前没有“份数”“消耗完再洗回”的真实抽牌堆模型。
- 如果奖励池唯一候选不足 3 张，当前会 warning 并退化为“二选一 / 一选一”。
- 奖励 UI 对 Inspector 接线完整性敏感；当前策略是缺失奖励面板/按钮/卡牌点击链路时直接报错暴露，而不是继续吞错。
- 奖励库、抽牌库和卡牌总资产已经分层，但还没有更细粒度的权重表、过滤器和来源标签。

## 修改准则

- 短期内优先保证“准备期抽牌 -> 结算 -> 奖励选择 -> 下一回合”闭环稳定。
- 如果要做真正 deckbuilding，再引入牌堆耗尽、洗回、份数和来源追踪，不要把当前生成式实现硬凑成伪牌堆。
- 奖励相关改动必须同时检查：
  - `GameConfig.rewardLibrary`
  - `RewardService`
  - `TurnManager`
  - `UICardRewardPanel`
  - `UI手动配置与验收.md`

## 手工验收点

- 首回合和普通回合是否从正确的牌库抽牌。
- 手牌满时，奖励卡是否正确进入弃牌堆。
- 结算结束后是否正常弹出奖励面板，并允许“选一张”或“跳过”。
- 选择奖励后是否继续推进到下一回合，而不是停留在结算等待态。
- 加成回合与普通回合的奖励候选范围是否符合当前规则。
## 专题扩充约定

- 50 卡方案已经把牌库真源拆成 `FirstTurnPool`、`NormalTurnPool`、`RewardPool` 三套显式库，`AllCards` 继续保留为全量总库。
- 当前权重机制仍然沿用 `CardLibrary.cards` 的重复引用，不新增独立的权重字段或抽卡配置格式。
- 奖励侧仍维持“三选一”流程，专题文档里的池策略只描述偏向，不改变现有结算链路。
