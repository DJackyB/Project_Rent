# 卡牌与效果系统

## 模块职责

- 定义卡牌静态数据与运行时实例。
- 负责效果字符串的注册、解析、执行与校验。
- 决定一张卡在出牌时需要 `PlayArea` 还是 `Room` 目标。

## 核心数据结构

### `CardData`

- 关键字段：
  - `cardId`
  - `cardName`
  - `description`
  - `cardType`
  - `rarity`
  - `cost`
  - `baseRent`
  - `targetKind`
  - `preEffect`
  - `instantEffect`
  - `settleEffect`
  - `destroyEffect`
  - `durability`
  - `waitTurns`
- 当前约定：
  - `targetKind` 是出牌目标真源，决定这张卡是走 `PlayArea` 还是 `Room`。
  - `cardType` 只负责牌面类型语义，以及进入房间后占用哪类槽位。
  - `Tenant + PlayArea`、`Event + Room` 这类组合是允许的。

### `CardInstance`

- 运行时状态：
  - `CurrentDurability`
  - `CurrentWait`
  - `PlacedRoom`
  - `IsDestroyed`
- 创建时会把四类效果字段预解析为 `ICardEffect`。

### `GameContext`

- 当前提供：
  - `MoneyManager`
  - `BoardManager`
  - `EffectContext.SelectedRoom`

## 当前实现

### 效果注册与执行

- 所有效果统一在 [CardEffectRegistration.cs](../../Assets/_Assets/Scripts/Card/CardEffectRegistration.cs) 注册。
- [CardEffectFactory.cs](../../Assets/_Assets/Scripts/Card/CardEffectFactory.cs) 支持：
  - 单效果：`AddMoney;100`
  - 组合效果：`AddMoney;100|DrawCard;1`

### 目标类型判定

- 运行时已经不再由 `TurnManager` 或 `UICardDropZone` 直接用 `Contains("SelectedRoom")` 推断目标。
- 当前统一走 [CardTargeting.cs](../../Assets/_Assets/Scripts/GameFlow/CardTargeting.cs)：
  - 所有卡统一读取 `CardData.targetKind`
  - `Room` 目标表示出牌时必须给一个房间
  - `PlayArea` 目标表示可以直接打出
- 旧式效果字符串语义不再用于 UI 推断，但导表和启动期仍会对“依赖房间上下文”的效果做约束校验。

### 当前校验

- 启动时：
  - [GameManager.cs](../../Assets/_Assets/Scripts/Core/GameManager.cs) 会校验四类效果字段。
- 同时会校验 `targetKind` 是否合法，以及 `SelectedRoom` 效果是否要求 `Room` 目标。
- `ExpandSlot`、`MoveTenantToEmptyRoom` 这类虽然名字不含 `SelectedRoom`、但运行时依赖房间上下文的效果，也会被视为 `Room` 目标专用。
- 校验失败会直接中断初始化。
- 导表时：
  - [CardDataImporter.cs](../../Assets/_Assets/Scripts/Editor/CardDataImporter.cs) 会校验四类效果字段。
  - `targetKind` 是必填列，缺失或非法都会直接中断导表。
  - 未知 `cardType` 也会直接中断导表。

## 与其他模块的依赖

- 回合系统：
  - [TurnManager.cs](../../Assets/_Assets/Scripts/GameFlow/TurnManager.cs) 驱动出牌与结算。
- 棋盘系统：
  - 房间和合同相关效果依赖 `BoardManager`、`RoomSlot`。
- 经济系统：
  - 大部分数值效果最终落到 `MoneyManager`。
- 配置/导表：
  - 卡牌资产主要来自 Excel 导入和 `Assets/Resources/Cards`。

## 当前限制与风险

- 效果载体仍然是字符串，虽然校验已经补上，但长线可维护性仍不如结构化字段。
- `EffectContext.SelectedRoom` 还是全局临时状态，不适合承载“先选目标、后续多阶段持续引用”这类设计。
- 当前严格规则已经落地，但团队录表习惯和历史表格仍需要继续迁移。
- 启动期严格失败虽然更利于暴露问题，但也要求资产和表格必须保持持续整洁。

## 修改准则

- 新增效果时必须同时完成三件事：
  - 新增 `ICardEffect` 实现。
  - 在 [CardEffectRegistration.cs](../../Assets/_Assets/Scripts/Card/CardEffectRegistration.cs) 注册。
  - 更新相关文档与导表说明。
- 新增“需要选房间”的事件/合同卡时，必须显式配置 `targetKind`，不要把目标规则藏在效果命名里。
- UI 不直接写效果逻辑，只消费 `TurnManager` 和 `CardTargeting` 给出的结果。

## 手工验收点

- 普通事件卡是否仍可进入 `PlayArea` 并正常结算。
- `Tenant + PlayArea` 是否可以直接打出且不占房间槽位。
- `Event + Room` 是否必须选房间，且不会因为即时结算被塞进房间。
- 导表时错误效果字符串是否能被及时中断。
- `targetKind` 配错时，启动是否会直接报错并中断。
## 专题扩充落地

- 本轮 50 卡扩充已经补齐 `AddRoom` 和 `AddMoneyBySelectedRoomTenantCount`。
- `ExpandSlot` 已支持“房间目标事件通过 `SelectedRoom` 生效”，不再只认驻留房间。
- `TriggerSelectedRoomSettle` 已改成安全版额外结算：
  - 额外结算不扣耐久。
  - 禁止嵌套额外结算。
  - 额外结算中跳过同样带 `TriggerSelectedRoomSettle` 的卡，避免递归。
- 销毁补偿继续统一写在 `destroyEffect`，不额外引入 `AddMoneyOnCardDestroyed`。
