# 存档模块

## 当前状态

- 模块本体已入库并可编译。
- `EditMode` 测试已存在，说明底层协议、序列化和存储实现可独立验证。
- BaoZuPo 项目侧仍未正式接线；当前主链路不自动保存、不自动读档、也没有存档 UI。

## 模块职责

- 提供通用存档协议、序列化、存储和 section 组织能力。
- 为项目侧后续实现“存什么、何时存、何时读、如何暴露到 UI”预留稳定边界。

## 当前保留范围

当前主干保留的是通用模块目录：

- `Assets/Modules/Martian/Save/**`
- `Assets/Tests/EditMode/Save/**`

当前仍不存在项目接线层：

- `Assets/Scripts/Runtime/Save/**`
- 面向 BaoZuPo 的存档 Facade / Bootstrap / Slot UI
- 游戏进度、语言设置、房间状态、金钱状态等项目专用 `SaveSection`

## 当前工程里的真实含义

- 这套模块已经是“可复用的通用能力”。
- 但当前 BaoZuPo 主链路没有任何正式接线，所以不能把它视为“游戏已经支持存档”。
- 现阶段的正确表述应是：
  - 模块已导入。
  - 底层测试存在。
  - 项目功能未启用。

## 后续如果要接线

必须由项目侧显式补齐以下内容：

1. Save Facade / Bootstrap。
2. 项目专用 `SaveSection` 定义。
3. 启动时恢复与运行时触发点。
4. 存档槽位、错误提示和手工验收路径。

## 修改准则

- 通用模块内不要混入 BaoZuPo 项目语义。
- 项目接线层如果重建，建议单独放在 `Assets/Scripts/Runtime/Save/**` 或等价接入目录。
- 文档里必须明确区分“已导入”“底层可测”和“项目已启用”。
