# 存档模块

## 当前状态

- 已导入模块本体
- 未接线启用
- 当前主干没有 BaoZuPo 项目侧的存档 Facade、Section、启动入口或 UI 接入

## 模块职责

- 提供通用存档协议、序列化、存储和 section 组织能力。
- 为项目侧后续自行实现“存什么、何时存、何时读、如何接 UI”预留稳定边界。

## 当前保留范围

当前主干保留的是通用模块目录：

- `Assets/_Assets/Martian/Save/**`
- `Assets/_Assets/Tests/EditMode/Save/**`

当前没有保留的项目接线层：

- `Assets/_Assets/Scripts/Save/**`
- 游戏进度、语言设置、房间状态、金钱状态等 BaoZuPo 项目专用 Section

## 当前工程里的真实含义

- 这套模块已经能编译、能跑自身测试、也能作为通用能力继续复用。
- 但当前 BaoZuPo 主链路不会自动保存、自动读取，也没有任何 UI 按钮或启动流程去调用它。
- 因此当前项目状态应理解为：
  - “模块代码已入库”
  - 不是“项目已经支持存档”

## 后续如果要接线

必须由项目侧显式补齐以下内容：

1. Save Facade / Bootstrap
2. 项目专用 Section 定义
3. 启动时恢复与运行时触发点
4. 存档槽位、错误提示和手工验收路径

不建议再回到“模块一导入就隐式生效”的做法。

## 修改准则

- 通用模块内不要混入 BaoZuPo 项目语义。
- 项目接线层如果重建，必须单独放在 `Assets/_Assets/Scripts/Save/**` 或等价接入目录。
- 文档中必须明确写清“模块是否已启用”，不要让“已导入”和“已可用”混淆。
