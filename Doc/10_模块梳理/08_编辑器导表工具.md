# 编辑器导表工具

## 模块职责

- 从 Excel 读取卡牌配置并生成/更新 `CardData` 资产。
- 在导表阶段尽早发现效果配置和字段格式问题。
- 提供少量一次性辅助脚本，支持样例数据和旧表头迁移。

## 关键入口脚本

- [CardDataImporter.cs](../../Assets/Scripts/Editor/CardDataImporter.cs)
- [CardEffectRegistration.cs](../../Assets/Scripts/Runtime/Card/CardEffectRegistration.cs)
- [CardEffectFactory.cs](../../Assets/Scripts/Runtime/Card/CardEffectFactory.cs)
- [CardTargeting.cs](../../Assets/Scripts/Runtime/GameFlow/CardTargeting.cs)

- Excel 主文件：
  - `Assets/Data/Excel/CardData.xlsx`

## 当前实现

### 导表流程

1. 读取 Excel。
2. 收集英文表头列索引。
3. 校验必填列是否完整。
4. 按行构建或更新 `CardData`。
5. 写基础字段、`targetKind`、效果字段。
6. 对四类效果字段执行 `CardEffectFactory.TryValidate(...)`。
7. 删除不再被表格引用的旧 `CardData` 资产。
8. 保存并刷新 `Assets/Resources/Cards`。

### 当前校验能力

- 导表前会先执行 `CardEffectRegistration.EnsureRegistered()`，避免校验时漏注册。
- 效果字段会在导表阶段直接报错，不再等到运行时才发现。
- `targetKind` 规则：
  - 现在是必填列。
  - 所有卡都显式填写，不再按 `cardType` 猜测。
  - 只要效果里使用 `SelectedRoom`，`targetKind` 就必须是 `Room`。
  - 非法值、缺失值、未知 `cardType` 都会直接中断导表。
- 非空行如果缺少 `cardId`、`cardName` 或数值列格式错误，也会直接中断导表。

### 辅助脚本定位

- `CardDataImporter.cs`
  - 新增 `Tools/BaoZuPo/Sync Card Libraries`，会同步 `AllCards / FirstTurnPool / NormalTurnPool / RewardPool`。

## 与其他模块的依赖

- 卡牌系统：
  - 输出 `CardData` 供运行时加载。
- 效果系统：
  - 依赖 `CardEffectFactory` / `CardEffectRegistration` 做语义校验。
- 目标系统：
  - 依赖 `CardTargeting` 做运行时判定和启动校验对照。

## 当前限制与风险

- 导表目前是失败即停止，不再帮内容自动回退或自动猜测。
- 导表能发现格式和关键语义问题，但还不能替代玩法层面的完整验证。
- 旧的“一次性修表头 / 回填 50 卡 Excel”脚本已移除，当前以 `CardData.xlsx -> Import Card Data -> Sync Card Libraries` 为唯一正式导表链路。

## 修改准则

- 新增效果或新增目标规则时，先补注册和导表校验，再补内容。
- `targetKind` 已经作为真源必填项，不要再回到兜底推断。
- 一次性脚本如果再次启用，先检查是否仍符合当前 Excel 结构。

## 手工验收点

- 导表后 `Assets/Resources/Cards` 是否正确新增或更新资产。
- 拼错效果 ID 时，导表是否能直接报错。
- Excel 缺少 `targetKind` 时，是否会直接中断导表。
- Excel 配错 `targetKind` 或 `cardType` 时，是否会直接中断导表。
- `SelectedRoom` 效果配成 `PlayArea` 时，是否会直接中断导表。
## 专题扩充约定

- 50 卡专题方案里，Excel 里会保留一列作者用 `词条` 作为流派/定位标签，但导表器不读取这列，仍以现有正式字段作为真源。
- 本轮已经把 `CardDataImporter` 扩成“导表后同步牌库与 `GameConfig`”的闭环工具。
