# 棋盘与房间系统

## 模块职责

- 管理房间集合与合同集合。
- 负责房间容量、放置规则、销毁清理。
- 向 UI 提供当前房间和合同的运行时状态。

## 关键入口脚本

- [BoardManager.cs](../../Assets/_Assets/Scripts/Board/BoardManager.cs)
- [RoomSlot.cs](../../Assets/_Assets/Scripts/Board/RoomSlot.cs)
- [TurnManager.cs](../../Assets/_Assets/Scripts/GameFlow/TurnManager.cs)
- [UIBoardPanel.cs](../../Assets/_Assets/Scripts/UI/UIBoardPanel.cs)

## 核心数据结构

### `BoardManager`

- `_rooms`
  - 当前所有房间。
- `_contracts`
  - 当前所有合同卡实例。
- `RoomCount`
- `ContractCount`

### `RoomSlot`

- `_maxTenantSlots`
- `_maxEquipmentSlots`
- `_tenants`
- `_equipments`
- `RoomIndex`

## 当前实现

### 初始化

`BoardManager.Initialize()` 会：

1. 初始化房间根节点。
2. 清空旧房间和合同列表。
3. 根据 `GameConfig` 初始值创建房间。

### 放置规则

- `Tenant` 只能进入租客槽。
- `Equipment` 只能进入设备槽。
- `Event` 和 `Contract` 不能直接放进 `RoomSlot`。
- `Contract` 通过 `BoardManager.AddContract()` 进入合同区。

### 容量规则

- 初始容量来自 `GameConfig`：
  - `defaultTenantSlots`
  - `defaultEquipmentSlots`
- `ExpandSlotEffect` 当前只会调用 `RoomSlot.ExpandTenantSlots()`，即只增加租客容量。

## 与其他模块的依赖

- 核心流程：
  - `TurnManager` 在结算期遍历房间和合同。
- 卡牌系统：
  - 房间和合同里存放的是 `CardInstance`。
- UI：
  - `UIBoardPanel` 和 `UIRoomView` 直接根据房间和合同状态刷新。

## 当前限制与风险

- 当前 `UIRoomView.BuildSlots()` 固定生成 `1 个租客槽 + 3 个设备槽`，与 `RoomSlot` 的真实容量不是同一来源。
- 这意味着一旦房间容量可配或被扩容，UI 就可能和逻辑不一致。
- 合同系统代码已预留，但当前 `Assets/Resources/Cards` 里没有 `cardType: Contract` 的资产，说明内容层尚未接上。
- `BoardManager` 目前只处理最基础的房间/合同集合，不支持房型差异、房间标签、特殊房间规则。

## 修改准则

- 房间容量相关改动必须同步检查 UI 的槽位生成逻辑。
- 如果后续要做合同玩法，优先先补内容闭环，再考虑为合同单独拆系统。
- 不要在多个地方各自维护“房间可放几张卡”的规则，尽量统一从 `RoomSlot` 读取。

## 手工验收点

- 开局房间数是否等于 `GameConfig.initialRoomCount`。
- 租客和设备是否都受容量约束。
- 扩容卡生效后，逻辑容量是否变化，UI 是否同步变化。
- 合同卡接入后，合同区是否能被正确刷新和结算。
