## 运行时激活机制

### 为什么桥接层是激活的

`Martian.Localization.Unity.asmdef` 包含 `versionDefines`：

```json
{
  "name": "com.unity.localization",
  "expression": "1.0.0",
  "define": "MARTIAN_LOCALIZATION_PACKAGE"
}
```

`com.unity.localization 1.5.11` 已安装，因此该 define 在 `Martian.Localization.Unity` 程序集内自动生效。
`UnityLocalizationBridge.cs` 内的 `#if MARTIAN_LOCALIZATION_PACKAGE` 代码 **IS 编译并激活**。

> 注意：ProjectSettings 的 Scripting Define Symbols 中无需手动添加该符号，versionDefines 会在程序集范围内自动处理。

### 字体应用流程

`LocalizationFontUtility` 通过两个 `[RuntimeInitializeOnLoadMethod]` 钩子自动运行：

1. `BeforeSceneLoad` — 注册场景加载事件监听
2. `AfterSceneLoad` — 为所有已加载场景的 TMP Text 应用 SourceHanSansSC

字体 profile 路径：`Resources/Localization/LocalizationFontProfile`（位于 `Assets/Modules/Martian/Localization/Resources/` 下）。

### 桥接层初始化流程

`UnityLocalizationRuntimeInstaller`（在 `UnityLocalizationBridge.cs`）：

1. `SubsystemRegistration`：重置 `LocalizationServices`
2. `BeforeSceneLoad`：创建 `UnityLocalizationBootstrap` 并调用 `Initialize()`，注册 `UnityLanguageService` 和 `UnityLocalizedTextService`

初始化后 `LocalizationServices` 持有的是真实的 Unity Localization 实现，不再是 Null 实现。

## 文案调用层

### GameText.cs（UI 固定文案）

```
GameText.cs
  ↓ LocalizationServices.Resolve(table="GameText", entry="GameText.Turn", fallback="Turn {0}")
  ↓ UnityLocalizedTextService.Resolve()
↓ StringDatabase.GetTable("GameText") → Assets/Data/Localization/GameText_zh-Hans.asset
  ↓ GetEntry("GameText.Turn") → 中文条目
  ↓ 返回中文文案 ✅
```

GameText 表由 **GameTextLocalizationMigrator**（`Tools → BaoZuPo → Localization → Text Tools`）生成：
1. Parse GameText — 解析 `GameText.cs` 所有条目
2. Export CSV — 导出 `GameText.csv`
3. Import CSV — 填入 zh-Hans 翻译
4. Generate Table — 写入 Unity Localization 表

中文条目已生成，游戏内 UI 文案正常显示中文。

### CardText.cs（卡牌名称/描述）

```
CardText.cs
  ↓ LocalizationServices.Resolve(table="Card", entry="Card.{id}.Name", fallback=cardName)
  ↓ UnityLocalizedTextService.Resolve()
  ↓ StringDatabase.GetTable("Card") → 存在
  ↓ GetEntry("Card.{id}.Name") → zh-Hans 条目
  ↓ 返回中文名称
```

**已生效。** `UICardView.cs` 直接调用 `CardText.Name()` / `CardText.Description()`，卡牌名称和描述显示中文。

## 卡牌本地化工作流

卡牌中文文案的真源是 CardData 资产的 `cardName` / `description` 字段（由 Excel 导表写入）。

同步流程：
```
CardData.xlsx（cardName/description 列）
  → CardDataImporter → CardData.asset
  → CardLocalizationSyncUtility（手动触发）
  → Card_zh-Hans.asset
  → 运行时通过 CardText.cs 展示
```

同步工具入口：`Tools → BaoZuPo → Localization → Advanced → Cards → Sync Card Tables`

导表后如果卡牌中文名有变化，需手动重新同步。

## 当前限制

- **无语言切换 UI**：运行时没有语言选择入口。默认语言由 `Localization Settings → Project Locale` 决定，启动优先级：PlayerPrefs → SystemLocale → ProjectLocale。
- **Common/UI 表未被调用**：`Martian/Localization/Project/Tables/` 下的 UI 和 Common 表无代码引用，属于冗余资产。
- **GameText 表需手动维护**：新增 `GameText.cs` 条目后，需在 Text Tools 重走 Parse → Export CSV → Import CSV → Generate Table 四步。
- **ProjectLocale 必须配置**：`UnityLocalizationBootstrap` 不再有硬编码兜底，`Localization Settings → Project Locale` 未设置时启动报错。
- **当前仍是单场景落地**：现状已在 `SampleScene` 中跑通，但没有额外场景或设置页对语言切换做覆盖验证。

## 修改准则

- **不要重新引入硬编码中文字符串**，中文内容应通过 CardData 字段 → 导表 → 本地化表的链路流转。
- **不要绕过 CardText.cs 直接读 CardData.cardName** 在 UI 上显示，保持本地化调用面统一。
- **修改 UI 固定文案**时走 `GameText.cs`，不要在 UI 组件里直接 SetText。
- **卡牌改名或改描述**后，导表完成后需手动运行 Sync Card Tables，否则运行时中文文案不更新。

## 手工验收点

- 运行游戏后 Inspector 中 TMP Text 组件的 Font Asset 是否是 SourceHanSansSC（不是默认 LiberationSans）
- 卡牌名称和描述是否显示中文
- UI 固定文案（回合数、阶段名、按钮等）是否显示中文
- 修改 CardData.xlsx 并重新导表 + Sync Card Tables 后，运行时卡牌名称是否更新
- 新增 GameText.cs 条目后，在 Text Tools 里重新走四步流程后，新文案是否正确显示
