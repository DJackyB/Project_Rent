# 本地化模块

## 当前状态

- `Martian.Localization` 模块已导入
- `com.unity.localization` 依赖已进入工程
- 当前主干尚未把这套模块接到 BaoZuPo 运行时主链路上
- 项目当前仍在实际使用轻量本地化链路：`LocalizationManager + UIStrings + UIFontCatalog`

## 模块边界

### 当前已导入的通用模块

- `Assets/_Assets/Martian/Localization/**`

职责：

- 抽象语言服务与文本服务协议
- 提供运行时字体应用工具
- 提供 Unity Localization 桥接层

### 当前仍在运行的项目实现

- [LocalizationManager.cs](../../Assets/_Assets/Scripts/UI/LocalizationManager.cs)
- [UIStrings.cs](../../Assets/_Assets/Scripts/UI/UIStrings.cs)
- [UIFontCatalog.cs](../../Assets/_Assets/Scripts/UI/UIFontCatalog.cs)

职责：

- 当前语言来源与切换
- 系统 UI 文案入口
- 中文字体与 TMP 字体应用

## 当前工程里的真实状态

- 玩家可见 UI 仍然通过 `LocalizationManager.UseChinese` 驱动文案切换。
- `Martian.Localization` 目前只是代码层导入，不会自动替代旧实现。
- 当前主干没有 BaoZuPo 项目接线层，例如：
  - `BaoZuPoLocalizationBootstrap`
  - `GameText`
  - `CardTextResolver`
  - 对 `TurnManager` / `UIManager` / `UICardView` 的整体接入替换

也就是说，当前项目状态应理解为：

- “轻量本地化方案仍在跑”
- “通用本地化模块已入库，但尚未启用”

## 后续如果要切到模块化本地化

需要先做清楚这几个决定：

1. 谁是唯一真源：
   - 继续以 `LocalizationManager/UIStrings` 为真源
   - 还是切到 `Martian.Localization + Unity Localization`
2. 项目接线层放在哪里
3. 语言设置是否需要与后续存档接线一起处理
4. 旧链路何时删除，而不是长期双轨并存

在这些决定明确之前，不建议把两套链路同时视为“当前实现”。
