# 跳字反馈模块

## 当前状态

- 状态：V1 已落地
- 模块本体：`Assets/_Assets/Martian/Feedback/`
- 项目接线：`Assets/_Assets/Scripts/Integration/Martian/Feedback/`
- 目标：在当前项目内形成“通用反馈模块 + 项目接线层”的结构，后续可继续复用

## 模块职责

- 接收业务层发出的通用反馈请求
- 按目标分轨播放跳字反馈
- 在模块不可用时自动降级为 NoOp
- 保证反馈播放失败不会中断游戏流程

## 目录结构

- `Assets/_Assets/Martian/Feedback/Core/`
  - 通用接口、请求模型、枚举
- `Assets/_Assets/Martian/Feedback/Runtime/`
  - 服务定位、NoOp 降级、播放协调器、启动入口
- `Assets/_Assets/Martian/Feedback/Presets/`
  - 通用样式预设
- `Assets/_Assets/Scripts/Integration/Martian/Feedback/BaoZuPo/`
  - 当前项目的房间/合同/全局目标映射

## 运行时结构

### 启动

- `UIManager` 在启动时创建并配置 `FeedbackBootstrap`
- `FeedbackBootstrap` 根据 `GameConfig` 决定启用真实服务还是 NoOp

### 播放

- `FeedbackPlaybackCoordinator` 维护“目标 key -> 播放轨道”的映射
- 单条轨道内部复用 `UISequenceTextController`
- 不同目标独立播放，互不抢占

### 降级

以下情况会自动退化到 NoOp：

- `enableFeedback = false`
- `enableMoneyFeedback = false`
- 启动入口未创建
- 播放器创建失败

退化行为：

- 业务照常执行
- 不等待反馈完成
- 不抛出阻断主流程的异常
- 只丢失跳字表现

## Feel 视觉增强层（已接线）

状态：**底层与顶层已接线，等待人工 Play Mode 验收**。

Feel v5.9.1 作为可选视觉后端，通过 Composite 模式挂在现有反馈链路下。不替换 FloatingText，不参与时序控制。

### 运行时链路

```
BaoZuPoFeedbackAdapter（不变）
  └─▶ FeedbackServiceLocator → FeedbackPlaybackCoordinator
        └─▶ CompositeFeedbackPlaybackBackend
              ├── 主：FloatingTextFeedbackBackend  ← 控制时序
              └── 副：FeelFeedbackBackend          ← 视觉增强，handle 丢弃
```

### 集成代码

位于 `Assets/_Assets/Scripts/Integration/Feel/`：

| 文件 | 职责 |
|------|------|
| `CompositeFeedbackPlaybackBackend` | 组合主/副后端，副后端异常不阻断主后端 |
| `FeelFeedbackBackend` | 将 FeedbackRequest 映射到 MMF_Player slot |
| `FeelFeedbackSlots` | slot 名称常量（MoneyDelta / SettlementStep / LoanPayment / CardPlay / RewardReveal） |
| `BaoZuPoFeelFeedbackInstaller` | MonoBehaviour 接线器，Start 时构造 Composite 并注入 bootstrap |

### 当前场景与资源

- 场景：`Assets/Scenes/SampleScene.unity`
- 节点：`Canvas/FeelFeedbackInstaller`
- 节点：`Canvas/FeelFeedbackPlayers`
- 场景内播放器：
  - `MoneyDeltaFeedbackPlayer`
  - `SettlementStepFeedbackPlayer`
  - `LoanPaymentFeedbackPlayer`
  - `CardPlayFeedbackPlayer`
  - `RewardRevealFeedbackPlayer`
- 复用 prefab：`Assets/_Assets/Prefabs/Feedback/Feel/`

### 降级策略

- Installer 不存在 → 静默降级，FloatingText 照常
- bootstrap 引用为 null → LogError + 自我禁用
- 某个 MMF_Player 为 null → LogWarning，该类别跳过 Feel 增强
- MMF_Player 运行时异常 → Composite catch 吞掉，主后端不受影响

## 修改准则

- 真实数值变化仍以业务系统为真源，反馈模块只负责表现，不反向决定结果。
- 模块本体和项目接线必须分开维护，不要再把 BaoZuPo 语义写回 `Martian/Feedback/**`。
- 新增反馈时，优先走 `BaoZuPoFeedbackAdapter`，不要让业务脚本直接拼装播放请求。
- Feel 相关代码只放在 `Integration/Feel/`，不进入 `Martian/Feedback/`。
- 玩法核心脚本不直接依赖 `MoreMountains.*`。

## 后续扩展建议

- 如果要接耐久/等待，先把直接字段写入收口成统一入口
- 如果要迁移到别的项目，优先先抽 `Core + Runtime + UI`，再替换业务适配层
- 如果反馈种类继续增多，再考虑把样式配置提成 `ScriptableObject`
- Feel 新增 slot 时，同步更新 `FeelFeedbackSlots` 常量和 `FeelFeedbackBackend.ResolveSlot()` 映射
