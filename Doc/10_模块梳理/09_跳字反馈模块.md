# 跳字反馈模块

## 当前状态

- 状态：V2 已落地
- 当前主链路：`Assets/_Assets/Scripts/UI/Common/FeedbackPopup/`
- 项目适配层：`Assets/_Assets/Scripts/Integration/Martian/Feedback/BaoZuPo/BaoZuPoFeedbackAdapter.cs`
- 结算播放层：`Assets/_Assets/Scripts/UI/Settlement/UISettlementSequenceController.cs`
- 目标：用项目内可复用的 UI popup 层承载小丑牌风格跳字，保留通用扩展边界，避免业务脚本直接操作表现细节。

## 模块职责

- 接收业务侧的资金反馈语义，例如出牌扣款、即时收益、贷款扣款、结算步骤和最终入账。
- 根据 UI 锚点和偏移显示短促弹出的 popup。
- 根据类别统一处理正收益、扣款、倍率、最终入账的颜色和字号。
- 通过完成回调保证结算步骤按顺序播放，popup 播放完成后再推进后续流程。
- 保持通用层和业务适配层分离，popup view 不直接依赖包租婆业务、Feel 或多语言服务。

## 目录结构

- `Assets/_Assets/Scripts/UI/Common/FeedbackPopup/`
  - `UIFeedbackPopupLayer`：统一入口，负责查找/创建 popup layer，支持 `popupPrefab`。
  - `UIFeedbackPopupView`：单个 popup 视图，负责背景、文字、色条和动画。
  - `UIFeedbackPopupRequest`：通用请求对象，包含 `Anchor`、`Text`、`Category`、`ScreenOffset`、`Style`、`TextConfigurator`、`AnchorFeedback`、`Completed`。
  - `UIFeedbackPopupStyle`：通用样式参数，控制颜色、字号、面板尺寸、停留时间和弹出曲线。
  - `UIFeedbackPopupCategory`：通用类别，包含 `positive`、`negative`、`multiplier`、`final` 等。
- `Assets/_Assets/Scripts/Integration/Martian/Feedback/BaoZuPo/`
  - `BaoZuPoFeedbackAdapter`：把出牌扣款、即时资金变化、贷款扣款转换为 popup 请求。
  - `BaoZuPoMartianFeedbackIntegration`：目前只同步 `GameConfig.enableMoneyFeedback`，用于控制资金 popup 是否启用。
- `Assets/_Assets/Scripts/UI/Settlement/`
  - `UISettlementSequenceController`：把结算 step 和最终入账转换为 popup 队列，并等待完成回调。

## 运行时链路

### 出牌和贷款

```
TurnManager
  -> BaoZuPoFeedbackAdapter.PublishPlayCost / PublishInstantMoneyDelta / PublishLoanPayment
  -> UIFeedbackPopupLayer.Show(...)
  -> UIFeedbackPopupView.Play(...)
```

### 结算

```
TurnManager / GameEvents.SettlementSequenceQueued
  -> UISettlementSequenceController.Queue(...)
  -> PlayPopupSettlementStep(...)
  -> UIFeedbackPopupLayer.Show(...)
  -> Completed 后播放下一步
  -> 最终入账 popup 播完后发布结算播放完成事件
```

## 定位规则

- popup 的位置由 `Anchor + ScreenOffset` 决定。
- `Anchor` 是目标 UI 的 `RectTransform`，例如房间、合同卡、play area 或钱栏。
- `ScreenOffset` 是在目标中心点基础上的屏幕像素偏移。
- 钱栏相关 popup 通过 `UIManager.ResolveMoneyTargetAnchor()` 获取锚点。
- `UITopBar.MoneyTargetAnchor` 可以在 Inspector 指向一个手摆的 `MoneyPopupAnchor`。
- `UITopBar.PlayCostPopupVerticalGap` 控制出牌扣款和贷款扣款离钱栏锚点的高度。
- `UITopBar.SettlementTotalPopupVerticalGap` 控制结算最终入账离钱栏锚点的高度。
- `UITopBar` 现在默认尊重场景里已绑定的 HUD 文本布局；只有运行时自动创建的文本才会应用默认布局。若需要旧的运行时强制布局，可打开 `Use Runtime Generated Layout`。

## 样式与动画

- 默认样式由代码生成，也支持在 `UIFeedbackPopupLayer.popupPrefab` 指定 prefab。
- 默认动画是小丑牌风格的短促弹出：缩小入场、快速 overshoot、回弹稳定、短暂停留、上移淡出。
- `positive` 默认绿色背景，`negative` 默认红色背景，`multiplier` 默认蓝色背景，`final` 默认金色背景。
- popup 出现时会通过 `AnchorFeedback` 触发来源锚点轻微 punch。
- `AnchorFeedback` 是通用回调，后续可替换为 Feel `MMF_Player`，不需要改 `UIFeedbackPopupView`。

## 文案与字体

- 文案仍由业务侧提供。
- 出牌扣款走 `GameText.FeedbackCost(...)`。
- 贷款扣款走 `GameText.FeedbackLoan(...)`。
- 结算步骤走 `GameText.SettlementBase / SettlementBonus / SettlementMultiplier / SettlementFinal`，卡牌加成可使用 `CardText.Name(...)`。
- `UIFeedbackPopupView` 不直接依赖本地化系统。
- `UIFeedbackPopupLayer.DefaultTextConfigurator` 默认调用项目侧字体配置，确保中文字体能跟随当前项目设置；如果未来抽成插件，可以把该配置改为外部注入或置空。

## 旧链路清理状态

- 资金 popup 主链路已经不再发布 `FeedbackRequest` 或 `FeedbackSequenceRequest`。
- `UISettlementSequenceController` 不再保留旧结算跳字 fallback，也不再暴露 `Use Popup Settlement Feedback` 开关。
- 旧 `play-cost` 分类已移除。
- `UIManager` 不再强依赖 `FeedbackBootstrap`，只同步 `GameConfig.enableMoneyFeedback`。
- `Martian/Feedback` 和 `Integration/Feel` 基础设施仍保留，供未来其它非资金反馈或 Feel 增强使用。

## 当前已接入

- 出牌扣款：钱栏上方红色 popup。
- 即时资金变化：房间、合同卡或 play area 附近的正负 popup。
- 贷款扣款：钱栏上方红色 popup。
- 结算房租、加成、倍率和最终值：按结算队列顺序逐条播放 popup。
- 结算最终入账：钱栏上方最终 popup，播完后继续结算完成流程。

## 手工验收

1. Play 后打出有 cost 的牌，确认钱栏上方出现红色 `Cost -xx`。
2. 触发贷款扣款，确认同样出现在钱栏上方。
3. 打出有即时收益/损失的牌，确认对应来源附近出现 `+xx` 或 `-xx`。
4. 进入结算，确认房间/合同卡来源 popup 按顺序播放。
5. 结算最终入账在 `Money Target Anchor` 上方显示，并且播完后能继续进入奖励或下一流程。
6. 调整 `MoneyPopupAnchor`、`PlayCostPopupVerticalGap`、`SettlementTotalPopupVerticalGap`，确认位置变化符合预期。
7. 切换语言或字体配置后再次触发 popup，确认文字不乱码、不缺字。

## 修改准则

- 真实数值变化仍以业务系统为真源，popup 只负责表现，不反向决定结果。
- 新增资金类跳字优先走 `UIFeedbackPopupLayer` 和 `UIFeedbackPopupRequest`。
- 通用 popup 层不要直接依赖包租婆业务、Feel 或多语言服务；需要项目能力时通过 request 回调或 layer 默认配置注入。
- 如果需要美术精修，优先做带 `UIFeedbackPopupView` 的 prefab，再拖到 `UIFeedbackPopupLayer.popupPrefab`。
- 如果要接入 Feel，优先通过 `AnchorFeedback` 或业务侧适配层触发，不要让 `UIFeedbackPopupView` 直接依赖 `MoreMountains.*`。
