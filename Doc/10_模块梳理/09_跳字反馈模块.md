# 跳字反馈模块

## 当前状态

- 状态：V1 已落地
- 模块本体：`Assets/_Assets/Martian/Feedback/`
- 项目接线：`Assets/_Assets/Scripts/Integration/Martian/Feedback/`
- 目标：在当前项目内形成“通用反馈模块 + 项目接线层”的结构，后续可继续复用

## 模块职责

- 接收业务层发出的通用反馈请求
- 按目标分轨播放跳字反馈
- 在模块不可用时自动降级为 NoOp
- 保证反馈播放失败不会中断游戏流程

## 目录结构

- `Assets/_Assets/Martian/Feedback/Core/`
  - 通用接口、请求模型、枚举
- `Assets/_Assets/Martian/Feedback/Runtime/`
  - 服务定位、NoOp 降级、播放协调器、启动入口
- `Assets/_Assets/Martian/Feedback/Presets/`
  - 通用样式预设
- `Assets/_Assets/Scripts/Integration/Martian/Feedback/BaoZuPo/`
  - 当前项目的房间/合同/全局目标映射

## 公共接口

### `IFeedbackService`

- `bool IsAvailable`
- `void Publish(FeedbackRequest request)`
- `void PublishSequence(FeedbackSequenceRequest request)`

### 核心数据

- `FeedbackRequest`
  - 单次反馈
- `FeedbackSequenceRequest`
  - 多步序列反馈
- `FeedbackStep`
  - 序列中的单步

### 核心枚举

- `FeedbackCategory`
  - `Money`
  - `Settlement`
  - `Cost`
  - `Loan`
- `FeedbackTargetKind`
  - `Room`
  - `Card`
  - `Global`
- `FeedbackChannel`
  - `FloatingText`
  - `Sequence`

## 运行时结构

### 启动

- `UIManager` 在启动时创建并配置 `FeedbackBootstrap`
- `FeedbackBootstrap` 根据 `GameConfig` 决定启用真实服务还是 NoOp

### 播放

- `FeedbackPlaybackCoordinator` 维护“目标 key -> 播放轨道”的映射
- 单条轨道内部复用 `UISequenceTextController`
- 不同目标独立播放，互不抢占

### 降级

以下情况会自动退化到 NoOp：

- `enableFeedback = false`
- `enableMoneyFeedback = false`
- 启动入口未创建
- 播放器创建失败

退化行为：

- 业务照常执行
- 不等待反馈完成
- 不抛出阻断主流程的异常
- 只丢失跳字表现

## 当前项目适配

由 [BaoZuPoFeedbackAdapter.cs](../../Assets/_Assets/Scripts/Integration/Martian/Feedback/BaoZuPo/BaoZuPoFeedbackAdapter.cs) 负责：

- 房间目标 -> 房间锚点
- 合同目标 -> 合同卡锚点
- 事件/贷款 -> 全局锚点或屏幕中心回退

当前 V1 已接入：

- 结算房租
- 结算加成
- 结算最终值
- 出牌花费
- 即时资金收益
- 贷款扣款

- 自定义可视化编辑器

## 修改准则

- 真实数值变化仍以业务系统为真源，反馈模块只负责表现，不反向决定结果。
- 模块本体和项目接线必须分开维护，不要再把 BaoZuPo 语义写回 `Martian/Feedback/**`。
- 新增反馈时，优先走 `BaoZuPoFeedbackAdapter`，不要让业务脚本直接拼装播放请求。

## 后续扩展建议

- 如果要接耐久/等待，先把直接字段写入收口成统一入口
- 如果要迁移到别的项目，优先先抽 `Core + Runtime + UI`，再替换业务适配层
- 如果反馈种类继续增多，再考虑把样式配置提成 `ScriptableObject`
