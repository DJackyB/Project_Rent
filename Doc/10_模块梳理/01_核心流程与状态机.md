# 核心流程与状态机

## 模块职责

- 负责启动期加载核心配置、卡牌数据和牌库数据。
- 负责驱动 `Prepare -> Action -> Settle -> Reward -> Next Turn` 的单回合闭环。
- 负责向 UI 和其它系统广播阶段、回合、奖励、结算完成、GameOver 等关键事件。
- 负责通过 NodeCanvas FSM 推进场景内的回合状态机。

## 核心状态与事件

- `GamePhase`
  - `Prepare`
  - `Action`
  - `Settle`
- `TurnManager.ActionPhaseEnded`
  - 行动阶段是否已被手动结束。
- `TurnManager.IsSettlementPlaybackPending`
  - 当前是否还在等待结算表现播放完成。
- `TurnManager.IsRewardSelectionPending`
  - 当前是否还在等待奖励三选一结果。
- `GameEvents`
  - `TurnStarted`
  - `PhaseChanged`
  - `SettlementPlaybackCompleted`
  - `CardRewardOffered`
  - `CardRewardSelected`
  - `TurnEnded`
  - `GameOver`

## 当前实现

### 启动初始化

`GameManager.Awake()` 当前会执行：

1. 注册卡牌效果。
2. 加载 `CardDatabase`。
3. 加载 `CardLibraryDatabase`。
4. 校验 `GameConfig.firstTurnDrawLibrary / normalTurnDrawLibrary / rewardLibrary`。
5. 校验已加载卡牌的效果字段与目标类型。
6. 初始化 `MoneyManager`。
7. 初始化 `BoardManager`。
8. 初始化 `DeckManager`。
9. 构建 `GameContext`，供卡牌效果与结算流程复用。

### 场景状态机

当前 `SampleScene` 中的 NodeCanvas FSM 仍是标准回合闭环：

1. `PrepareStage`
2. `ActionStage`
3. `CheckStage`
4. 回到 `PrepareStage`

对应脚本分别调用：

- `TurnManager.ExecutePreparePhase()`
- `TurnManager.StartActionPhase()`
- `TurnManager.ExecuteSettlePhase()`

`GameOver` 当前仍主要依赖 `GameManager.OnGameOver(...)` 在运行时主动停止 `FSMOwner`，而不是依赖图内显式分支跳转。

### 单回合主流程

#### Prepare

- 回合数 `+1`
- 广播 `TurnStarted`
- 执行场上卡牌 `PreEffect`
- 按首回合 / 普通回合规则，从 `GameConfig` 指定牌库抽牌
- 清理已销毁卡牌

#### Action

- 广播阶段变化
- 等待玩家出牌或手动结束行动阶段
- `ActionPhaseEnded` 是 `Action_SettlePhase` 进入结算的切换条件之一

#### Settle

- 广播阶段变化
- 逐房间结算租客基础收益与房间内卡牌 `SettleEffect`
- 逐合同结算 `SettleEffect`
- 扣减耐久与等待回合
- 执行贷款扣款
- 缓存本回合奖励是否为 `boosted`
- 生成结算表现批次，并等待 `SettlementPlaybackCompleted`

#### Reward

- 结算表现播完后，`TurnManager.TryStartRewardOrComplete()` 决定是否进入奖励环节
- 奖励来源是 `GameConfig.rewardLibrary`
- `TurnManager.AwardOneCardFromThreeOptions(...)` 会发布 `CardRewardOffered`
- `UIManager -> UICardRewardPanel` 负责展示三选一面板
- 玩家选择或跳过后，UI 发布 `CardRewardSelected`
- `TurnManager.OnCardRewardSelected(...)` 决定是否把奖励卡加入手牌，并结束本回合

#### Turn End

- 只有在“结算表现播完”且“奖励选择完成或无需奖励”后，才会广播 `TurnEnded`

## 与其它模块的依赖

- 卡牌系统
  - 依赖 `CardDatabase`、`CardLibraryDatabase`、`CardEffectFactory`
- 棋盘系统
  - 依赖 `BoardManager` 提供房间、合同、场上卡牌集合
- 牌库系统
  - 依赖 `DeckManager` 处理抽牌、移除手牌、奖励入手与等待牌过期
- 经济系统
  - 依赖 `MoneyManager` 处理租金、费用、贷款与 GameOver 判定
- UI 系统
  - 主要通过 `GameEvents`
  - 奖励闭环额外依赖 `UIManager -> UICardRewardPanel`

## 当前限制与风险

- `Condition_CheckGameOver.cs` 已存在，但当前 FSM 图里仍不是显式的 `GameOver` 分支闭环。
- `GameManager.InitializeSystems()` 现在已经改成核心 manager 缺失直接 fail-fast，因此场景接线错误会更早暴露。
- 奖励链路仍然依赖 `UIManager` 正确挂接 `UICardRewardPanel`；区别是现在缺失时会直接报错暴露配置问题，而不是继续静默等待。
- `TurnManager` 当前同时承担阶段推进、出牌校验、结算、贷款、奖励等职责，后续继续堆逻辑时要特别警惕复杂度继续上升。

## 修改准则

- 不要绕过 `TurnManager` 直接在 UI 或其它脚本里推进回合。
- 新增阶段规则时，优先判断应落在 `Prepare / Action / Settle / Reward` 哪一段，而不是散落到 UI 事件里。
- 调整奖励链路时，要同时检查 `TurnManager`、`Action_SettlePhase`、`UIManager`、`UICardRewardPanel` 是否仍然能闭环。
- 修改 `GameConfig` 抽牌或奖励配置时，要同步回看 [04_牌库与奖励系统.md](./04_牌库与奖励系统.md) 和 [07_配置与数据管线.md](./07_配置与数据管线.md)。

## 手工验收点

- 开局后是否能稳定进入 `Prepare -> Action -> Settle`
- 首回合和普通回合的抽牌来源是否符合 `GameConfig`
- 行动阶段结束后是否能正常进入结算
- 结算表现播完后是否会正确出现奖励三选一
- 奖励选择与跳过两条路径是否都能进入下一回合
- 贷款扣款失败后是否真正停止回合推进
