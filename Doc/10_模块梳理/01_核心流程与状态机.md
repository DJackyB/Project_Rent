# 核心流程与状态机

## 模块职责

- 负责初始化核心系统。
- 负责推进单回合生命周期。
- 负责向 UI 和其他系统广播关键游戏事件。
- 负责通过 NodeCanvas FSM 驱动场景内的回合状态机。

## 核心数据结构

- `GamePhase`
  - `Prepare`、`Action`、`Settle`。
- `CardPlayTargetKind`
  - `PlayArea`、`Room`。
- `CardPlayValidationResult`
  - 出牌目标类型、阻塞原因、目标房间的统一返回结构。
- `GameEvents`
  - 金钱、回合、阶段变化、结算跳字、GameOver 等广播事件。

## 当前实现

### 初始化

`GameManager.Awake()` 会执行：

1. 统一注册卡牌效果。
2. 加载 `CardDatabase`。
3. 对已加载卡牌做效果字段校验。
4. 初始化 `MoneyManager`。
5. 初始化 `BoardManager`。
6. 初始化 `DeckManager`。
7. 构建 `GameContext` 供卡牌效果执行时使用。

### 场景状态机

当前 `SampleScene` 中的 NodeCanvas FSM 是一个固定闭环：

1. `PrepareStage`
2. `ActionStage`
3. `CheckStage`
4. 回到 `PrepareStage`

对应脚本分别调用：

- `TurnManager.ExecutePreparePhase()`
- `TurnManager.StartActionPhase()`
- `TurnManager.ExecuteSettlePhase()`

另外，`GameManager.OnGameOver(...)` 现在会主动调用场景中同物体上的 `FSMOwner.StopBehaviour(false)`，避免 GameOver 后继续空转状态机。

### 单回合主流程

#### Prepare

- 回合数 `+1`
- 广播 `TurnStarted`
- 执行场上卡牌 `PreEffect`
- 按首回合/普通回合规则抽牌
- 清理已销毁卡

#### Action

- 进入 `Action` 阶段
- 等待玩家出牌或手动结束行动阶段
- `ActionPhaseEnded` 是 NodeCanvas 状态切换的结束信号

#### Settle

- 广播阶段变化
- 逐房间结算租客基础收益和房间内卡牌 `SettleEffect`
- 逐合同结算 `SettleEffect`
- 扣减耐久和等待回合
- 执行贷款扣款
- 若未 GameOver，则发放奖励卡
- 广播 `TurnEnded`

## 与其他模块的依赖

- 卡牌系统：
  - 调用 `CardInstance` 上预解析的各类效果。
- 棋盘系统：
  - 读取房间、合同、场上卡牌。
- 经济系统：
  - 扣费、加钱、贷款判断都依赖 `MoneyManager`。
- 牌库系统：
  - 抽牌、手牌移除、奖励入手、等待卡过期处理。
- UI：
  - 主要依赖 `GameEvents` 做刷新和表现。

## 当前限制与风险

- `Condition_CheckGameOver.cs` 已存在，但当前场景 FSM 连接里仍未接入显式 GameOver 分支。
- 目前是靠 `GameManager.OnGameOver(...)` 在运行时主动停止 `FSMOwner`，可以先保证停机，但图本身的表达还不够完整。
- `TurnManager` 目前同时承担了阶段推进、出牌校验、结算、贷款、奖励等职责，短期可接受，但后续扩展要警惕继续堆逻辑。
- 当前回合状态机只覆盖标准循环，不包含暂停、重开、失败后停机等显式分支。

## 修改准则

- 不要绕过 `TurnManager` 直接在 UI 或其他脚本里推进阶段。
- 新增阶段规则时，优先考虑是否应该落在 `Prepare/Action/Settle` 其中一段，而不是零散插在 UI 里。
- 如果调整 NodeCanvas FSM，必须同步更新本文件与风险评估文档。
- GameOver 相关改动优先补齐停机路径，而不是继续在 UI 层“看起来像结束”。

## 手工验收点

- 开局后是否能稳定进入 `Prepare -> Action -> Settle`。
- 行动阶段结束按钮和调试键是否都能推进到结算。
- GameOver 触发后是否真正停止继续推进回合。
- 首回合和普通回合抽牌数是否正确。
