# 核心流程与状态机

## 模块职责

- 负责启动期加载核心配置、卡牌数据和牌库数据。
- 负责驱动 `Prepare -> Action -> Settle -> Reward -> Next Turn` 的单回合闭环。
- 负责向 UI 和其它系统广播阶段、回合、奖励、结算完成、GameOver 等关键事件。
- 负责通过 `TurnFlowService.RunAsync` 推进场景内的回合状态机；NodeCanvas FSM 仅保留为调试/原型工具。

## 核心状态与事件

- `GamePhase`
  - `Prepare`
  - `Action`
  - `Settle`

- `TurnManager.IsSettlementPlaybackPending`
  - 当前是否还在等待结算表现播放完成。

## 当前实现

### 启动初始化

`GameManager.Awake()` 当前会执行：

1. 注册卡牌效果。
2. 加载 `CardDatabase`。
3. 加载 `CardLibraryDatabase`。
4. 校验 `GameConfig.firstTurnDrawLibrary / normalTurnDrawLibrary / rewardLibrary`。
5. 校验已加载卡牌的效果字段与目标类型。
6. 初始化 `MoneyManager`。
7. 初始化 `BoardManager`。
8. 初始化 `DeckManager`。
9. 构建 `GameContext`，供卡牌效果与结算流程复用。

### 场景状态机

当前 `SampleScene` 中的正式主流程由 `TurnFlowEntryPoint` 启动 `TurnFlowService.RunAsync`。NodeCanvas FSM 保留在场景里作为调试/原型图，但 `FSMOwner` 默认禁用，不再自动驱动回合。`GameManager.Awake()` 也会在默认配置下提前停用同物体上的 `FSMOwner`，避免旧流程在 VContainer entry point 启动前抢跑。

1. `PrepareStage`
2. `ActionStage`
3. `SettleStage`
4. 回到 `PrepareStage`

正式 async flow 分别调用：

- `TurnManager.ExecutePreparePhase()`，等待抽牌表现完成。
- `TurnManager.StartActionPhase()`，等待 `ActionPhaseEnded`。
- `TurnManager.ExecuteSettlePhase()`，等待结算表现、奖励和结算后随机事件完成。

`GameOver` 会让 async loop 在下一次等待点停止；`GameManager.OnGameOver(...)` 仍保留对旧 `FSMOwner` 的停止逻辑，服务于调试回退。

### 单回合主流程

#### Prepare

- 回合数 `+1`
- 广播 `TurnStarted`
- 执行场上卡牌 `PreEffect`
- 按首回合 / 普通回合规则，从 `GameConfig` 指定牌库抽牌
- 清理已销毁卡牌

#### Action

- 广播阶段变化
- 等待玩家出牌或手动结束行动阶段
- `ActionPhaseEnded` 是 `Action_SettlePhase` 进入结算的切换条件之一

#### Settle

- 广播阶段变化
- `TurnManager.ExecuteSettlePhase()` 暂时作为兼容门面
- `SettlementService.ResolveAsync(...)` 负责房间收益、合同收益、耐久、销毁、手牌等待清理、贷款和 GameOver 规则
- `SettlementService` 只返回 `SettlementResult`，不创建 UI batch
- `SettlementPresentationMapper` 把 `SettlementResult` 转成 `UISettlementPlaybackBatch`
- `SettlementPresentationService` 提交表现批次，并等待 `SettlementPlaybackCompleted`

#### Reward

- 结算表现播完后，`TurnManager.TryStartRewardOrComplete()` 决定是否进入奖励环节
- 奖励来源是 `GameConfig.rewardLibrary`
- `RewardService.OfferAndWaitChoiceAsync(...)` 生成候选并发布 `CardRewardOffered`
- `UIManager -> UICardRewardPanel` 负责展示三选一面板
- 玩家选择或跳过后，UI 发布 `CardRewardSelected`
- `RewardService` 等待选择结果；`TurnManager` 负责奖励入手动画和结束本回合

#### Turn End

- 只有在“结算表现播完”且“奖励选择完成或无需奖励”后，才会广播 `TurnEnded`

## 与其它模块的依赖

- 卡牌系统
  - 依赖 `CardDatabase`、`CardLibraryDatabase`、`CardEffectFactory`
- 棋盘系统
  - 依赖 `BoardManager` 提供房间、合同、场上卡牌集合
- 牌库系统
  - 依赖 `DeckManager` 处理抽牌、移除手牌、奖励入手与等待牌过期
- 经济系统
  - 依赖 `MoneyManager` 处理租金、费用、贷款与 GameOver 判定
- UI 系统
  - 主要通过 `GameEvents`
  - 奖励闭环额外依赖 `UIManager -> UICardRewardPanel`

## 当前限制与风险

- `Condition_CheckGameOver.cs` 已存在，但当前正式流程不再依赖 FSM 图分支；GameOver 由 `TurnFlowService` 的等待条件停止 loop。
- `GameManager.InitializeSystems()` 现在已经改成核心配置和 manager 缺失直接 fail-fast，因此场景接线错误会更早暴露。
- 奖励链路仍然依赖 `UIManager` 正确挂接 `UICardRewardPanel`；区别是现在缺失时会直接报错暴露配置问题，而不是继续静默等待。
- `TurnManager` 仍承担阶段执行兼容门面；出牌、结算、奖励候选/等待、商店状态已经开始拆到 Application Service。
- `GameLifetimeScope` 已作为场景级 VContainer 装配入口接入，负责注册已拆出的 Application Service、`TurnFlowService` 并启动 `TurnFlowEntryPoint`。
- Phase 5 已补 `TurnFlowServiceTests` 自动化覆盖 `Prepare -> Action -> Settle -> Reward skip -> next turn`，但仍需要 Unity Editor 中手工跑完整 3 回合体验链路。

## 修改准则

- 不要绕过 `TurnManager` 直接在 UI 或其它脚本里推进回合；命令式玩法动作优先进入对应 Application Service。
- 新增阶段规则时，优先判断应落在 `Prepare / Action / Settle / Reward` 哪一段，而不是散落到 UI 事件里。
- 调整奖励链路时，要同时检查 `RewardService`、`TurnManager`、`TurnFlowService`、`UIManager`、`UICardRewardPanel` 是否仍然能闭环。
- 修改 `GameConfig` 抽牌或奖励配置时，要同步回看 [04_牌库与奖励系统.md](./04_牌库与奖励系统.md) 和 [07_配置与数据管线.md](./07_配置与数据管线.md)。

## 手工验收点

- 开局后是否能稳定进入 `Prepare -> Action -> Settle`
- 首回合和普通回合的抽牌来源是否符合 `GameConfig`
- 行动阶段结束后是否能正常进入结算
- 结算表现播完后是否会正确出现奖励三选一
- 奖励选择与跳过两条路径是否都能进入下一回合
- 贷款扣款失败后是否真正停止回合推进
