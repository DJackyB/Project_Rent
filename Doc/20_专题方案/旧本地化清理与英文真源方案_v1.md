# 旧本地化清理与英文真源方案 v1

> 状态：已落地
> 落地日期：2026-03-30
> 当前结论：项目已从“旧双语轻量本地化”收口到“英文单真源”

## 已执行内容

- 删除旧运行时本地化链路：
  - `LocalizationManager`
  - `UIStrings`
  - `UIFontCatalog`
  - `AppLanguage`
- 删除旧中文字体工具与资源：
  - `ChineseFontTools`
  - `Assets/Resources/Fonts/**`
- 新建 [GameText.cs](../../Assets/_Assets/Scripts/UI/GameText.cs) 作为英文单真源入口。
- 将 UI、结算、奖励与反馈的固定文案统一切到 `GameText`。
- 移除 `LanguageChanged`、`RefreshLocalization()`、运行时字体切换等旧链路。
- 将代码中残留的中文字符串字面量统一改成英文。

## 当前状态

- 运行时只有一套英文文案真源。
- 没有语言状态。
- 没有语言切换。
- 没有临时双语分支。
- `Martian.Localization` 仍保留为已导入未接线模块。

## 为什么这样收口

- 先清掉旧本地化逻辑，避免项目长期停留在真假两套真源并存的状态。
- 保留统一文案入口 `GameText`，避免把英文字符串重新散落到几十个脚本里。
- 未来如果重新接多语言，只需要替换 `GameText` 的内部实现，而不是再全项目搜字面量。

## 对未来多语言接入的建议

1. 保留 `GameText` 作为项目调用面。
2. 把 `GameText` 内部从直接返回英文字符串替换成 key-based provider。
3. 再决定是否正式接入 `Martian.Localization` 或 Unity Localization。

## 当前不做的事

- 当前不接 `Martian.Localization`
- 当前不接 `com.unity.localization`
- 当前不做语言切换 UI
- 当前不做翻译表与资源切换
