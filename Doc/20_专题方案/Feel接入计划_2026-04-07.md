# Feel v5.9.1 安装与首轮接入计划

## 摘要

- 目标包：[Feel v5.9.1](E:/SDL/Feel/Feel%20v5.9.1%20(08%20Dec%202025).unitypackage)。
- 安装策略：完整导入 Feel 包，但首轮只做视觉反馈增强。
- 音频边界：音频继续由 `Martian.Audio`、`AudioEventBridge`、`AudioCatalog` 作为唯一真源，不用 Feel 替换音频系统。
- 反馈边界：Feel 不替换现有 `Martian.Feedback`，只作为可选表现后端接在现有反馈链路下。

## 关键改动

- 安装步骤：
  - 创建隔离分支，例如 `codex/install-feel-591`。
  - 用 Unity 导入完整包：`AssetDatabase.ImportPackage("E:/SDL/Feel/Feel v5.9.1 (08 Dec 2025).unitypackage", false)`。
  - 导入后先只做编译和 Console 检查；如果 Feel optional integrations 引发编译错误，停止接入并报告，不直接改 vendor 代码。
- 新增集成层：
  - `CompositeFeedbackPlaybackBackend : IFeedbackPlaybackBackend`：主后端为现有 `FloatingTextFeedbackBackend`，副后端为 Feel；`Publish/PublishSequence` 返回主后端 handle，确保结算阶段仍按现有完成信号推进。
  - `FeelFeedbackBackend : IFeedbackPlaybackBackend`：把 `FeedbackRequest / FeedbackSequenceRequest` 映射到配置好的 `MMF_Player` 视觉预制体，不处理音频。
  - `BaoZuPoFeelFeedbackInstaller : MonoBehaviour`：挂在 `Canvas/FeedbackBootstrap` 或其子对象上，显式引用 `FeedbackBootstrap` 和各类 `MMF_Player`，启用时调用 `SetBackend(compositeBackend)`。
- 首轮效果预制体放在 `Assets/_Assets/Prefabs/Feedback/Feel/`：
  - `MoneyDeltaFeedback`：金币增减飘字/轻微弹动，响应出牌费用、即时收益、结算总金额。
  - `SettlementStepFeedback`：结算时在房间/合约锚点附近出现轻量 pulse 或高亮，不改变结算顺序。
  - `LoanPaymentFeedback`：每 5 回合还贷时红色 UI 闪烁/金额强调，不用强 Camera Shake。
  - `CardPlayFeedback`：出牌成功时轻微缩放/光效，实际移动仍由现有 DOTween 拖拽逻辑负责。
  - `RewardRevealFeedback`：奖励三选一出现与选择时的淡入/选中反馈。

## 接线位置

- 结算、费用、即时金钱、贷款继续走 `Assets/_Assets/Scripts/Integration/Martian/Feedback/BaoZuPo/BaoZuPoFeedbackAdapter.cs`。
- 卡牌拖拽和奖励面板只在 UI 层接入，例如 `UICardDragController` 和 `UICardRewardPanel`，通过 Feel presenter/installer 调用，不让玩法核心脚本直接依赖 `MoreMountains.*`。
- `AudioEventBridge` 保持不变；所有 `MMF_Player` 里的 Audio/Sound feedback 首轮禁用或不配置。

## 验证计划

- 安装后验证：
  - Unity 编译完成后 Console 无项目侧 error。
  - `Assets/Feel/...` 已导入。
  - Package Manager 不新增第二套项目音频真源。
- 自动化：
  - 跑现有 EditMode 测试，当前基线是 `69/69 passed`。
  - 若新增 backend 测试，覆盖 Composite 返回主后端 handle、Feel 副后端不可用时不影响主反馈、启用 Feel 但缺必要 `MMF_Player` 时明确失败。
- 手工 Play Mode：
  - 开局进入 Action 阶段，手牌正常生成。
  - 拖拽卡牌：拖起、合法目标、非法返回、出牌成功都有视觉反馈，且卡牌实际出牌逻辑不变。
  - 结算阶段：房间/合约结算仍逐步播放，顶部金钱延迟显示仍正确，阶段不会因为 Feel 提前或延迟而卡住。
  - 贷款回合：扣款反馈出现，失败/破产流程仍正常。
  - 奖励三选一：面板出现、选择、跳过都能继续流程。
  - 音量设置仍控制所有实际音效；Feel 不绕过 `Martian.Audio` 播放声音。

## 假设与默认选择

- 完整导入 `Assets/Feel/...`，首轮不筛选删除 `FeelDemos / NiceVibrations / MMSoundManager`，先保证 vendor 包完整可编译。
- Feel 是可选表现层：未启用时游戏仍可玩；一旦启用但必要引用缺失，要在 Play 时明确报错，不做静默猜测或自动补齐。
- 首轮不接 URP Volume、Cinemachine、MMSoundManager、NiceVibrations；只做 Canvas/UI 级视觉反馈，避免影响发售前主链路稳定性。
