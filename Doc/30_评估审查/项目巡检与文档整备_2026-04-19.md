# 项目巡检与文档整备（2026-04-19）

> 巡检范围：当前仓库主干代码、`Doc/` 维护入口、Unity `EditMode` 测试基线  
> 巡检目标：修正文档和实际项目不一致之处，补齐缺失维护入口，并输出当前风险点与优化点  
> 验证方式：代码结构巡检 + 场景/资源抽查 + Unity MCP `EditMode` 测试

## 本轮已完成的文档整备

- 修正了 `Doc/README.md` 的推荐阅读和维护规则，把当前有效文档与历史归档区分开。
- 更新了存档、本地化、音频、CI/CD 模块文档，使其对齐当前真实路径 `Assets/...` 与主干接线状态。

## Findings

### P1：当前 `EditMode` 测试基线未通过，失败集中在商店/准备阶段主链路

- 本轮通过 Unity MCP 触发 `EditMode` 测试，结果为 `89` 个测试中 `8` 个失败。
- 失败测试集中在以下链路：
  - `CloseCurrentShop_PreventsReopeningInSameTurn`
  - `OpenShop_ClampsOfferCountToUiCapacity_WhenRuntimeConfigExceedsLimit`
  - `PlayCard_ShopCard_OpensShop_AndRemovesCardWithoutDiscard`
  - `ShopOpen_DeduplicatesOffers_AndAllowsMultiplePurchasesWithoutRefill`
  - `ShopPurchase_FailsWhenMoneyIsInsufficient`
  - 以及 `ExecutePreparePhase_*`、`ExecuteSettlePhase_*` 的准备/结算断言失败
- 其中多项直接抛 `ArgumentOutOfRangeException`，说明不是“测试预期变了”这么简单，而是商店候选或手牌/结算流程里已有可触发的索引越界风险。

建议：

- 先把这 8 个失败测试恢复到通过，再把后续玩法迭代压上去；否则文档里写得再清楚，主链路基线仍然不稳。

### P2：当前有效文档虽然开始回到正轨，但仍有一批活跃文档保留历史路径 `Assets/_Assets/...`

- `Doc/10_模块梳理/01_核心流程与状态机.md` 到 `09_跳字反馈模块.md` 仍大量引用旧路径。
- `Doc/20_专题方案/`、`Doc/20_代码审查/` 里也有不少旧路径和旧工作区绝对路径。
- 这会让维护者误判真实入口，尤其在需要快速定位脚本或排查接线状态时。

建议：

- 下一轮文档整理优先继续清理 `10_模块梳理/01-09` 的路径。
- `20_代码审查/20250403_代码质量审查报告.md` 这类“仍有参考价值但含历史路径”的文档，建议在文件头加上历史说明，或迁入归档并由新的 review 文档接棒。

### P2：随机事件已经进入主干运行链路，但文案与本地化工作流尚未统一

- 随机事件已经有 `RandomEventData.xlsx`、导表工具、`Resources` 资产、场景面板和效果桥接。
- 但它的标题/描述/选项文本当前直接依赖事件资产内容，没有像 `GameText` / `CardText` 一样统一走本地化表。
- 这在当前中文单语阶段还能接受，但会给未来双语或文案集中维护带来额外分叉。

建议：

- 等主链路稳定后，把随机事件文本并入现有本地化工作流，至少先统一“谁是真源、谁负责导出”。

### P2：CI 对 PR 不是默认强校验，而是依赖 `run-ci` 标签

- `unity-ci.yml` 虽然监听 `pull_request`，但 job 侧用了 `contains(..., 'run-ci')` 条件。
- 这意味着 PR 如果没有打 `run-ci` 标签，就不会真正执行 `EditMode` 测试。
- 当前主干又恰好已有 8 个本地失败测试，进一步放大了“漏跑 CI”的风险。

建议：

- 如果团队已经进入“主干稳态优先”阶段，建议把 PR 测试改为默认执行，而不是依赖手工打标。
- 如果仍想保留手工打标，应把这一规则写进协作流程，并在 PR 模板里明确提示。

### P3：Save 模块边界清楚，但项目侧仍没有正式存档方案

- `Assets/Modules/Martian/Save/**` 和 `Assets/Tests/EditMode/Save/**` 已存在。
- 但 BaoZuPo 项目侧没有正式 Facade / Bootstrap / Slot UI，也没有任何“何时保存、何时恢复”的主链路说明。
- 这是“能力已在仓库内，但功能未对玩家开放”的典型状态。

建议：

- 若近期不做存档，就保持现在这种“模块可复用、项目未启用”的明确表述。
- 若近期准备接线，应先出项目侧存档真源设计，避免把通用模块直接改成项目私有实现。
