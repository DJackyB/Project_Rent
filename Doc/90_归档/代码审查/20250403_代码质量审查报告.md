## 二、详细问题分析

### 问题 1: [EventBus.cs] - Domain Reload 清理不完整
**严重程度**：🔴 High  
**代码位置**：`Assets/_Assets/Scripts/Utilities/EventBus.cs:120-124`  
**具体表现**：
- RuntimeInitializeOnLoadMethod 的 SubsystemRegistration 阶段在很多系统初始化之前
- 如果在 Awake() 或 OnEnable() 中有订阅操作，而这些方法在 SubsystemRegistration 之后执行，旧的订阅可能仍然存在
- 没有日志输出来确认清理完成，难以调试

**潜在后果**：
- Domain Reload（重新进入编辑器播放、重启编辑器等）后可能产生重复订阅
- 内存泄漏：旧的回调函数仍被保持
- 事件系统状态混乱

**建议修复**：
```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
private static void ResetOnDomainReload()
{
    int count = _eventTable.Count;
    _eventTable.Clear();
    if (count > 0)
    {
        Debug.Log($"[EventBus] Cleared {count} event subscription(s) on domain reload.");
    }
}
```

**优先修复**：✅ 本周

### 问题 2: [UICardDragController.cs] - 多卡牌拖拽的竞态条件
**严重程度**：🔴 High  
**代码位置**：`Assets/_Assets/Scripts/UI/UICardDragController.cs:87-142`  
**具体表现**：
- BeginDrag 时检查 `_activeHandler != null` 并立即取消（第112-114行），但存在窄窄的竞态窗口
- 没有防止多点触控冲突：如果 PointerEventData 来自不同触摸点，系统会混乱
- 立即取消时没有检查卡牌是否已销毁，可能产生异常

**潜在后果**：
- 多点触控设备上（平板、手机）可能同时响应多个卡牌
- 快速切换卡牌时拖拽状态混乱
- UI 显示与实际状态不同步

**建议修复**：
```csharp
public void BeginDrag(UICardDragHandler handler, PointerEventData eventData)
{
    if (handler == null || handler.CardView == null || handler.CardView.Card == null)
    {
        return;
    }

    // 检查是否已在拖拽同一卡牌
    if (_activeHandler != null)
    {
        if (_activeHandler == handler)
        {
            return; // 已在拖拽同一个卡牌，忽略重复事件
        }
        
        // 不同卡牌：安全地取消前一个
        // 只在非完成状态下取消（防止在出牌完成流程中接受新拖拽）
        if (!_isCompletingPlay)
        {
            CancelActiveDrag(true);
        }
        else
        {
            return; // 在完成出牌流程中，拒绝新的拖拽
        }
    }
    
    // ... 其他初始化代码
}
```

**优先修复**：✅ 本周

### 问题 5: [MoneyManager.cs] - 事件发送时序不一致
**严重程度**：🟠 Medium  
**代码位置**：`Assets/_Assets/Scripts/Economy/MoneyManager.cs:96-133`  
**具体表现**：
```csharp
// 余额不足时（第104-115行）：
if (!CanAfford(amount))
{
    EventBus.Publish(new GameEvents.MoneyInsufficient(amount));  // 先发事件，金额未改变
    return false;
}

// 成功支付时（第125-130行）：
_currentMoney -= amount;  // 先改变金额
EventBus.Publish(new GameEvents.MoneyChanged(_currentMoney, _currentMoney - amount));  // 后发事件
```

- `MoneyInsufficient` 事件发布时，金额仍为旧值
- `MoneyChanged` 事件发布时，金额已是新值
- 这种不一致的事件时序很危险

**潜在后果**：
- 监听器（如 UI）接收事件时，查询余额会得到不同步的值
- UI 显示混乱或闪烁
- 其他系统依赖金额变化事件时可能出现逻辑错误

**建议修复**：
统一为"先改变后通知"模式，或在事件中携带新旧值：
```csharp
public bool ReduceMoney(int amount)
{
    // ... 验证
    
    int oldMoney = _currentMoney;
    _currentMoney -= amount;
    
    // 发送事件时金额已改变
    EventBus.Publish(new GameEvents.MoneyChanged(_currentMoney, oldMoney));
    
    // 检查破产
    if (_currentMoney < 0)
    {
        EventBus.Publish(new GameEvents.MoneyInsufficient(amount));
    }
    
    return true;
}
```

**优先修复**：✅ 本迭代（与事件系统设计审查一起）

### 问题 8: [EventBus & 订阅者] - 订阅清理不完整
**严重程度**：🟠 Medium  
**代码位置**：全局搜索 `Subscribe`，检查对应 `Unsubscribe`  
**具体表现**：
- GameManager.cs 和 TurnManager.cs 在 OnDisable 时正确取消订阅
- 但其他地方（如 RuntimeEventBusBridge）没有配对的 Unsubscribe
- UI 元素被销毁时订阅仍保留

**潜在后果**：
- UI 销毁后仍有悬垂回调，试图访问已销毁的 UI 元素
- NullReferenceException 在不可预料的时刻发生
- 长期运行时内存泄漏累积

**建议修复**：
1. 审查所有订阅点，确保都有对应的取消订阅
2. 建立规范：每个 OnEnable Subscribe 都要有 OnDisable Unsubscribe
```csharp
private void OnEnable()
{
    EventBus.Subscribe<GameEvents.CardPlayed>(OnCardPlayed);
    EventBus.Subscribe<GameEvents.SettlementSequenceQueued>(OnSettlementQueued);
}

private void OnDisable()
{
    EventBus.Unsubscribe<GameEvents.CardPlayed>(OnCardPlayed);
    EventBus.Unsubscribe<GameEvents.SettlementSequenceQueued>(OnSettlementQueued);
}
```

**优先修复**：✅ 本迭代（全局搜索检查）

### 问题 16: [BoardManager.cs] - 房间查询效率可优化

**建议修复**（可选）：
```csharp
// 为不同类型的房间维护快速索引
private List<RoomSlot> _roomsWithFreeTenantSlots = new();
private List<RoomSlot> _roomsWithFreeEquipmentSlots = new();

// 在 PlaceCard 时维护索引
public void PlaceCard(...)
{
    // ...
    UpdateAvailabilityIndex(room);
}

private void UpdateAvailabilityIndex(RoomSlot room)
{
    bool hasFreeTenant = room.CanAddTenant();
    if (hasFreeTenant && !_roomsWithFreeTenantSlots.Contains(room))
    {
        _roomsWithFreeTenantSlots.Add(room);
    }
```
