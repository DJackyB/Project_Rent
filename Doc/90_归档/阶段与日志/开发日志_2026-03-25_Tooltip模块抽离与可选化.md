# 开发日志 2026-03-25：Tooltip模块抽离与可选化

## 1. 本次目标

- 把当前项目里的 Hover/Tooltip 能力从“场景依赖的具体实现”改为“宿主保留接口、运行时模块可抽离”的结构。
- 保证 Tooltip 模块缺席时，游戏流程和 UI 主链路仍然可运行。
- 同步补齐文档和最小 EditMode 测试骨架。

## 2. 本次关键实现

### 2.1 宿主稳定层

- 新增 `UI/Common/Tooltip/` 目录。
- 新增：
  - `ITooltipService`
  - `ITooltipContentProvider`
  - `TooltipRequest`
  - `TooltipContent`
  - `TooltipPlacementMode`
  - `TooltipTrigger`
  - `TooltipServices`
  - `NullTooltipService`
- 业务层统一改为依赖 `TooltipServices.Current`。

### 2.2 运行时 Tooltip Core

- 新增 `UI/Common/Tooltip/Runtime/` 目录。
- 实现 `TooltipRuntimeService`，在启动时自动注册。
- Tooltip root 改为在运行时按所属 `Canvas` 懒创建。
- 新增 presenter 注册机制与定位工具类。

### 2.3 当前项目卡牌适配

- 新增 `UI/Common/Tooltip/Runtime/CardTooltipPresenter.cs`。
- 当前项目继续保留“复制卡牌 prefab 做放大预览”的视觉策略。
- 手牌、房间租客、房间设备、合同区统一接入 `TooltipTrigger + ITooltipContentProvider`。

### 2.4 调用链调整

- `UIManager` 不再依赖 `HoverPreviewController.Instance`。
- `UICardDragController` 拖拽开始时统一调用 `TooltipServices.Current.HideAll()`。
- `UICardView` 改为生成 `TooltipRequest`，不再依赖具体 Hover controller。

### 2.5 资产与场景调整

- `Card.prefab` 挂载的触发脚本语义已迁移到 `TooltipTrigger`。
- `SampleScene` 已移除旧的 `HoverPreviewRoot` 与 `CardHoverPreviewPresenter` 场景节点。

## 3. 这次刻意保留的东西

- 宿主项目仍永久保留一层 Tooltip no-op 契约壳。
- 老的 Hover 相关代码文件暂未一次性全部删除，避免扩大本轮改动范围。
- 卡牌 presenter 仍然是项目适配层，不强行做成完全通用内容展示器。

## 4. 这次没做的事

- 未做 Play Mode 自动化测试。
- 未在 Unity 编辑器内跑完整手工验收。
- 未把 Tooltip 内容类型扩展到卡牌以外的对象。
- 未处理移动端长按与手柄焦点交互。

## 5. 后续建议

1. 进 Unity 后先做一轮手工回归：手牌、房间租客、房间设备、合同区 Tooltip 与拖拽链路。
2. 验证 Tooltip 运行时模块缺席时，主链路是否只少 Tooltip 不报错。
3. 如果后续有第二个项目复用需求，再把 `TooltipContentKind` 和 presenter 扩展机制继续通用化。
